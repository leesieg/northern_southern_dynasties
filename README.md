# 风云南北朝

桌面浏览器单人策略游戏。当前为地图与旅行骨架，地图已参考 MapStage 升级为真实 DEM 与矢量图层，完整产品设计见 [落地方案.md](落地方案.md)。

## 本地运行

需要 Node.js 22.12+（本次在 25.6.1 验证）。

```bash
npm ci
npm run dev
```

入口：<http://127.0.0.1:5173>。仅监听本机，不公开发布。

```bash
npm test
npm run build
npm run preview
```

构建输出到 `dist/`；游戏规则仍在本地运行，不需要账号、API 密钥或云端模型。高清地图按视野联网请求 Mapterhorn 与 OpenFreeMap；网络不可用时保留低精度本地底图并提示。

部署到鲤世界时使用 `npm run build -- --base /games/fengyun-nanbeichao/`，入口为 `/games/fengyun-nanbeichao/`。此版本需登录主页账号，存档保存在该账号下；本地开发入口仍使用浏览器 IndexedDB。两个来源的存档不会自动合并，可从原入口导出文件，再在账号版本中导入。注销账号会删除该账号的游戏存档。

## 当前可以做什么

- 浏览覆盖中国及周边的真实高程地图，查看海拔设色、山影和分级水系；切换势力、城域、地形、道路模式与平面/立体视角。
- 缩放时分层显示地名，近景显示城墙、城门与楼阁符号；人物旗标与行程同步，点选整块城域，悬停查看摘要，双击拉近，右键预览路线；目录支持键盘选择与自动定位。
- 在 53 个城市／县治、63 条设计道路构成的网络上规划和执行旅行；扣除行粮、逐日移动、抵达暂停。
- 查看三个后台行旅的移动和事件；暂停、加速、单步推进；标签页隐藏时自动暂停。
- 消费盘缠补充行粮，记录真实的资源变化。
- IndexedDB 存档、三份轮换自动存档、一份手动存档、导入导出及版本与一致性校验。导入或恢复前保存原进度。
- 通过 Web Locks 防止多个标签页同时改写存档；地图加载异常可重试。

当前有 53 个地理锚点和四名设计人物，尚未建立 400—600 个战略地区、历史人物库及数千人物模拟。城市营建和庄园建设已接入规则；官职授予、战争、家族继承、完整历史事件和 AI 接入尚未实施。地图原型不等于已经达到 CK3 的美术完成度。

## 人工验收

UI 未使用浏览器自动化、computer use 或截图比对验证。请在桌面浏览器手动检查：

1. 地图可见；观察青藏高原、秦岭与江南平原的地形层次和水系。切换平面/立体视角，再用人物定位进入城邑近景，检查城墙楼阁、标签与旗标。
2. 拖动、缩放和全国视野正常，图层切换不重置人物或存档，署名链接可见。
3. 悬停、单击、双击和右键操作城域，检查高亮、提示和菜单；按 Escape 关闭菜单。点击海面或城域外不应误选远方城邑。打开地点目录，选择京口或长安；查看路径和粮食消耗，启程后加速观察，抵达时自动暂停。
4. 切换道路模式与行旅踪迹，确认地图标记和纪事相符。
5. 手动保存，推进数日，再恢复；导出文件后重新导入。刷新后可恢复最近存档。
6. 打开第二个标签页，确认它等待使用权；关闭原页后，等待页应自动进入。切换后台后返回，确认世界已暂停。

Windows/macOS 浏览器兼容性、图形性能、布局与美术表现仍待实机人工验收。移动端完整操作不在当前范围内。

## 数据来源与表示边界

- 设计参考：[MapStage](https://github.com/hopechen067/MapStage)，固定参考版本 da43a271c9a0f59f63b4cffb6ce8aade239d37e6。采用其古地图配色、DEM 晕渲和矢量水系的图层思路；MIT 许可随项目保留。
- 渲染层：MapLibre GL JS 6.10.0。原先的 Three.js 程序化山丘和栅格化海岸已移除，核心模拟与存档格式保持不变。
- [Mapterhorn](https://mapterhorn.com/attribution/)：Terrarium 编码真实高程。图层颜色自定义，三维起伏轻度夸张；按视野联网请求，不是历史地貌复原。
- [OpenFreeMap](https://openfreemap.org/) / OpenMapTiles / OpenStreetMap：只使用水面、自然河流和林地，不显示现代地名、行政区和道路。
- [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/) 1:110m 陆地与河流继续作为本地备用图层，公共领域。
- 53 块交互分区由地理锚点分区生成，共享边缘并裁切至 Natural Earth 陆地；势力外框合并同一组城域。这是游戏交互分区，不是历史郡县界。可用 `npm run data:territories` 离线重建（Node.js 22.12+ 的类型剥离实验功能）；城邑是夸张比例的战略建筑符号。坐标、道路与耗时仍是待考据的地理锚点及游戏参数，不作为 546 年史实。
- 未使用参考项目的展示媒体、卫星影像或现代国家/省界裁切数据，也未安装其全局技能。
- 完整来源、适配范围与第三方许可见 [THIRD_PARTY_NOTICES.md](public/THIRD_PARTY_NOTICES.md)。

## 546 年郡县与城市建设 · 当前实施范围

开局年份已由用户确认。新增 19 个县治：丹阳郡 7 个、京兆郡 7 个、魏尹 5 个；原有 34 个城市保留 ID 与旅行道路，吴郡节点显示为吴县，会稽节点显示为山阴。主要城市与县治按缩放分层显示。9 组郡级单位可查看州／郡／县路径、史籍县目、依据链接及核对状态。未定位县只列入名录，不生成假坐标。未覆盖地区仍显示归属待核。

北方以《魏书·地形志》为主，南方以《南齐书》州郡志为基底，并用《梁书》校读东扬州等变更。**不是全国 546 年完整区划复原**：较早地志与当年沿革、侨实关系尚须逐项核对。地块仍由近似锚点生成；郡级描边是分组合并，不能用来断言历史疆界、郡域面积或古城精确位置。来源索引在 `src/data/administration.ts`，游戏详情可直接打开原文。未导入 CHGIS 数据库、坐标或边界。

建设仅允许城市和独立家族庄园，州郡县多边形没有建设槽。城市市肆、城仓、驿舍要求治理权；初始角色未仕、无城市治理权，官职授予暂未接入，界面明确显示限制。庄园由沈氏家族持有，不要求城市治理权，主宅等级开放 1—3 种附属建筑，田庄、作坊、庄仓各可升至 3 级。所有建筑实际扣费，按游戏日完工，收益每 30 日结算；数值是游戏设计。采用 CK3 庄园作为持久家产的方向，未复刻其完整行政、继承或影响力系统。

存档世界结构升级到 v2，原 v1 存档通过校验后补充初始家产，原日期、人物、盘缠、行粮及在途行程保留；不清库。每次建设指令仍走 Worker 并自动保存。新增验证覆盖史料引用、县名与节点对应、工程扣费／竣工、建筑位、治理权限、城市收益、旧档迁移与异常存档拒绝。

人工验收入口：选择建康／长安／邺城 → 州郡县 → 点选县治；切换“郡县”查看合并郡界；左侧或地图打开“沈氏庄园” → 建田庄 → 关闭窗口并推进 10 日检查竣工，推进至第 30 日检查结算。城市营建应显示无治理权，并保持不可操作。

## 领地层级结构修正

旧实现只是城市邻域分区，不能满足独立领地层级。本轮新增稳定实体 ID 与父子关系：政权 → 州 → 郡／尹 → 县 → 城市。县与城市不再共享实体；右侧可逐层进入、回到上级、查看下级列表，地图按层级选择、描边和高亮；城市以外不显示营建与行程面板。未核实城市只挂到现有政权基底，不补造州郡县。该 546 年资料快照的有效区间是数据覆盖范围，不是单位的真实存续年代。

这次修正了层级结构，**没有完成历史疆域复原，也没有把原 Voronoi 几何变成历史县界**。现有合并描边明确标注为所录节点的覆盖示意。后续需要独立的、带来源与有效日期的行政边界版本，不能靠更多城市分区生成；行政隶属与军事控制也不能共用一个父节点字段。

历史面板目前只录入 553 年西魏攻取成都（《周书》卷二）与 554 年西魏攻陷江陵（《梁书》卷五）两条按年定位的城市事件。事件覆盖不完整，不提供跨年持续控制推断、不自动转移整郡、不改变游戏时钟、存档或治理权。点击时只定位与标记城市，并明确保留 546 行政基底。

资料检查：CHGIS 官方说明的完整时间切片主要是 1820 年，不能将下载到的近代郡县边界替代 546 年边界（https://chgis.fas.harvard.edu/pages/howto/）。尚未取得经过核实的 546 年全国县界及变更几何。下一项数据工作是选择可合法使用的历史地图底本，逐区域配准、绘制共享边界，再逐年校核拆分／合并／改隶／控制权变化；不把当前样机标为历史复原完成。

人工验收：右侧梁 → 扬州 → 丹阳郡 → 建康县 → 建康，逐层检查范围高亮、上级返回和城市独有操作；进入历史控制记录查看成都与江陵标记。非 UI 测试新增树无环、父子完整、县／城市分离、未知隶属不补造、基底不跨年外推与历史事件索引检查。

## 庄园画面

家族庄园采用一幅固定山水庭院底画，叠加主宅、田庄、作坊、庄仓的独立建筑图层。四种建筑各有三级外观；未建留空、开建显示工地，升级期间保留原建筑并叠加工地，完成后替换外观。画面直接读取世界等级与工程进度，读档后同步恢复，不另存视觉等级。点选画中建筑可选中对应营建卡，建设仍经原有扣费、建筑位与工期校验。

底画与透明图集位于 `public/art/estate/`，由 ImageGen 为本项目生成，未使用 CK3 图片；属美术想象，不是南朝建筑考古复原。新增 4 项非 UI 测试覆盖初始状态、施工／竣工切换、读档同步与独立等级。人工验收入口：打开“沈氏庄园”，检查点选建筑、兴建田庄的工地；关闭窗口推进 10 日，再打开检查田庄外观及恢复存档后的状态。画面布局与美术效果待用户人工验收。

## 最小可玩一局：立足江左

启动先显示资源加载提示，再进入主菜单；主菜单提供继续、新局说明／确认、读取本地槽及导入文件。右上角游戏菜单暂停世界，提供返回游戏、存档管理、保存并返回主菜单与说明。新局从 546 年建康开始：120 日内抵达京口领取委任（治理权、180 钱），建成京口一级市肆、沈氏一级田庄并返抵建康，即胜利；期限届满未完成则失败。目标卡给出下一步入口，抵达自动暂停，建设按游戏日推进。结局展示目标与余钱，冻结时间，可保存返回菜单或导出。委任为本局设计剧情，并非历史官职复原或通用任官系统。旧存档无 campaign 字段时仍按自由模式游玩。

新局保存前将现有局保留到独立 `previous-run` 槽（上一局备份），不参与三个自动槽轮换；再次新局会更新该备份。新局覆盖手动槽前在开局说明中明示。读档／导入先校验再备份，目标快照落盘成功后才替换世界；存储失败返回错误，不确认切换到主菜单。结局自动保存。资源加载、存档校验及多标签锁错误均显示明确反馈。

验证包括完整规则游玩（旅行→委任→两处营建→中途存档恢复→返程胜利）、超期失败与终局冻结、旧档兼容、非法任务状态拒绝，以及真实 Worker 消息处理函数与 fake-indexeddb 的菜单／继续／新局备份／读档／导入失败／存储失败／结局自动保存测试。该验证运行在非浏览器测试环境，不等同于真实浏览器 UI 验收。

人工验收入口：主菜单→新游戏→开启这一局→目标卡前往京口→出行启程→抵达后领取委任→营建市肆→庄园兴建田庄→关闭窗口并推进时间→返程建康→结局→保存返回主菜单。中途用游戏菜单保存退出，再继续或读取；另测导出／导入。观察加载、模型、目标卡、暂停与速度、存档提示及结局布局。可切至 7× 加快建设，时间暂停时工程不推进。

## 历史沙盒 Alpha：政务、财政与基础战争

新历史人物默认选择「历史沙盒」，不再在 120 日结束。原有教学局可在人物选择页切换，旧存档保留原来的教学／自由规则，不自动附加国家状态。存档列表区分历史沙盒与原有玩法。

左侧「政务」及局势卡进入统一面板：
- **财政与城邑**：个人／家产与公库分账，城市建设使用公款；户数、秩序、繁荣、税率、市肆与城仓影响公共预算，俸给进入个人钱袋。动员后的军饷与粮食负担会冲击财政。公库不足减发俸给；缺钱缺粮损害秩序。当前户数、数值与制度均为游戏参数。
- **任职与授权**：实际执政者可以任命同政权人物，其他人物通过与执政者交往请求任职或军务授权。任命文书按道路耗时加 7 日送达；送达时撤销前任权限，城市易手则失效。家业交接不自动继承公职与军务授权。当前没有完整派系、政变或皇位继承。
- **军事与议和**：动员、补给、逐日道路行军、同城交战、围城与议和；NPC 会动员应战并调整税制。先占领城市，再根据战争分数议和；只割让争夺目标，不能把整州郡边界推断为变化。停战 360 日，战争最迟 360 日自动结算。地图军旗显示位置与兵力，占领城市另作标记。政治底图仍是原剧本示意背景，军旗与城市控制提示才表示本局战况。
- **事务**：六类地方事件（模拟内容）每 90 日轮换，触发暂停与自动存档，明确费用和后果；资源不足可搁置，不会卡死。处理完关闭面板后继续时间。

军事暂为每国一支部队、单一边境战争，不含完整宣称、外交条款、多兵种、海战或完整军令通信；围城可从相邻己方控制城市补给，深入敌境需承担断粮；议和撤军为即时结算。长期模拟保留已录历史人物，不含自然死亡或出生。因此 50 年规则回放通过**不是**“完整跨代游戏已成熟”的证明。

主菜单原创背景 `/art/menu/realm-dawn.png` 已加入。现有庄园画、城市模型继续使用；人物肖像、衣饰、建筑考据、音效与音乐仍需制作。整个版本仍是 Alpha，完整验收差距见 `落地方案.md` 的“完整游戏推进基线”。尚不能宣称与 CK3 等量或已达到发行成熟度。

人工验收入口：新游戏→546 剧本→历史沙盒→萧衍→政务。检查税率／收支、城市与庄园扣款账户、任命送达后权限、军队地图标记、缺粮与议和、事件暂停、保存退出与继续。原教学局另验 120 日规则不变。严禁以浏览器自动化替代此次人工验收。

## 历史人物 3D 肖像

人物选择页、游戏内人物详情与历史名录接入按需加载的 Three.js 半身肖像。现有 11 位历史人物全部具有独立参数配置：脸宽脸长、下颌、颧部、鼻形、眼距、眉形、肤色、发须、成熟外观、冠帽、文服与甲胄。造型配置位于 `src/character/appearance.ts`，连续头部网格、五官、交领衣褶、冠帽、甲片及底座由 `src/character/model.ts` 生成。族内相似与个人差异为美术设计，不是测量或历史容貌结论。

拖动或左右按钮旋转，滚轮缩放，复位恢复肖像视角。「人物造型」可试穿文服／甲胄、切换神情并导出实际 GLB 网格用于外部三维工具。当前人物压力达到 80 时默认凝重，明确试选神情会覆盖这一预览；试装只作用于当前视图，不修改角色身份或存档。选人切换会复位试装，家业交接后当前肖像随角色 ID 更新。无需新开局，已有历史人物存档亦可显示模型。

模型按需绘制，没有持续动画循环；切换和关闭视图释放几何、材质、控制器与 WebGL 上下文。渲染不可用时显示错误及重试，不阻断人物资料与选择。CPU 模型检查覆盖全员网格有限性、包围盒、部件、差异、资源释放和 GLB 二进制导出，不能替代浏览器外观验收。

这是原创风格化半身模型首版，尚不是 CK3 的写实全身骨骼角色系统：没有皮肤贴图、完整骨骼动画、遗传捏脸或服饰年代考古复原。后续细化需人工确认此版造型与方向，不以代码检查宣称美术成熟。人工验收：选人时逐一切换 11 人、旋转正侧背面、文武试装、调整表情、导出 GLB、加载旧档查看人物详情并确认切换与关闭无异常。

### 人物质感第二轮

针对拼接感调整为连续面部曲面：鼻梁、鼻尖、颧部、眼窝、口周与下颌由同一头部网格塑形，移除独立鼻球与眼窝块。眼球下嵌，面部增加细微肤色变化；皮肤毛孔、织物经纬与发丝采用确定性的微表面凹凸纹理。衣领改为布片，减弱绳状衣褶，增加细发须；启用柔和阴影、主光／补光／轮廓光，并调整为肩部以上肖像构图。现有 11 人共享改善，仍保留个人参数。

这是程序化模型质量迭代，不等于完成 CK3 的专业雕刻、皮肤扫描、次表面散射与毛发制作流程；尚未经过用户视觉验收，不宣称同等写实质量。建议人工对照萧衍、高澄、独孤信的正面、侧面、文服与甲胄，确认面部接缝、眼睑、肤质、衣领和阴影。代码测试只检查网格／材质／释放与导出格式，不判定人物好看或逼真。

### 地方差事：天水粮务（2026-09-23）

成功给承办人功绩最多 +20，承办人与当前执政者双方交往积累各最多 +12，天水秩序最多 +12、繁荣最多 +4，并接济驻当地本国军队的补给；失败秩序最多 −8、在世双方交往积累各最多 −8。数值受已有系统上下限约束，功绩继续用于现有任职与军务授权。往来文书与状态支持存档导入导出；旧档新增空白差事状态，不补发事件。

### 中央公务、领主与个人能力（2026-09-24）

君主只保留中央官职，不再另设私人幕府。旧档君主幕僚解除编制后可重新任官，未完工工程保持原有预算及工期。普通官员与冒险者沿用幕府。中枢／度支解锁市肆、城仓、驿舍营建，中枢解锁大型水利工程，军务／选官解锁征募，度支／监察解锁清查征税。朝廷席位与城市提供公务入口；官员可自行立项，实际执政者可委派，统一经拟案、批款、赴任、办理与考绩。死亡、卸任、失城、忙碌和军队离驻会阻止办理；同城建设互斥，每季同类公务不可重复，公务不会自动授予城市治理权。

城市首部领主席位复用城市治理者实体与任命／申请弹窗。人物摘要增加外交、军事、管理、谋略四项能力，悬停显示基础、经历、特质、家族、重心、技能、研习和健康／压力构成。能力进入交涉接受度、公务效率、统军和营建成本；管理超过 12 点后每点减新工程造价 2%，最多 20%，与原加成合计最低造价 45%。在建项目保存报价，不随能力变化追改。

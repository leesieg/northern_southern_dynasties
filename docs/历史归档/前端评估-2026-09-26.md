# 《风云南北朝》前端评估报告

日期：2026-09-26 · 范围：`src/ui`（80+ 组件、47 个 CSS）、`docs/` 13 篇专题文档 + 68 篇更新日志 · 方式：只读审查，未改任何文件

## 总体结论

游戏视觉完成度高、主题统一（墨绿/旧金/纸色贯穿），`PersonSelection`/`HoverHint`/`DetailTabs` 等核心组件复用充分，Worker 会话层干净。主要问题不在"做没做到"，而在**一致性失控**：

1. **样式无 token 层**——921 个唯一色值、1240 处硬编码，旧金色一个色就有 25+ 个近似变体，每新增一个面板就多 1–2 个新色。
2. **四类问题反复返工**——更新日志 050–068 显示"信息重复 / 浮层遮挡 / 入口归属 / 长说明密度"每 3–5 轮复发一次，说明缺少机制化预防而非继续打补丁。
3. **死代码成规模**——`FacialPortrait` 整个组件、旧转盘/图例 CSS、`App.tsx` 的 characters 死分支、朝廷 dynast/movements 死页签。
4. **高风险交互缺陷**——宣战无二次确认；确认弹窗体系 ≥9 种手写 + 4 处 `window.confirm`；`HoverHint` 包裹器让键盘用户按两次 Tab 才能穿过一个动作。
5. **结构性债务**——`App.tsx` 是 900 行上帝组件，全项目仅 1 个 Context；打包体积警告从 057 挂到 068 从未处理。

- 方形头像/2:3 半身像比例执行一致；地图确无图例；顶部左右独立紧凑面板与约定一致。
- 对比度抽查整体过 WCAG AA，风险仅在 8–10px 弱色小字。

## 四、优化路线建议（按投入产出排序）

| 批次 | 内容 | 预期收益 | 风险 |
|---|---|---|---|
| 1 · 清理 | 死代码 6 项 + `.map-legend`/旧转盘 CSS；补 `--sans` 定义 | 减薄 ~10% 样式面，零行为变化 | 极低 |
| 2 · 安全 | 宣战加确认；统一危险操作确认组件；HoverHint 双 Tab 修复 | 消除最高危交互缺陷 + 39 处可访问性受益 | 低 |
| 3 · token 冻结 | 全局色板收敛 3–4 档 + 字号/间距阶梯；新代码只用变量，旧代码随改随迁 | 止住碎片化源头，回归可控 | 低（不追求一次迁移完） |
| 4 · 一致性组件 | 统一 Action 卡片 + ConfirmAction + 禁用原因范式；DetailTabs 全量替换手写页签 | 消灭"每面板一套交互"的返工模式 | 中（需逐面板替换） |
| 5 · 信息架构 | CityTab 拆分、财政四面板归轴、官职入口收敛、页签数收敛 | 消除状态歧义与多入口 | 中高（涉及状态与导航重构） |
| 6 · 架构 | 导航 Context 抽离，App.tsx 减负 | 后续所有改动的维护成本下降 | 中 |
| 7 · 存量债 | 打包体积（自 057 起每轮保留的大分包提示）、窄屏断点补齐、悬停 title 收敛 | 恢复构建健康度 | 低-中 |

另有三件**规划级空白**值得排期决策（`docs/规划/落地方案.md` 有、更新日志无）：宗教/寺院 UI、AI 交互接入、音效音乐。

## 五、机制化预防建议（治本）

更新日志显示四类问题已各复发 2–3 轮（信息重复、浮层遮挡/截获、入口归属、长说明密度）。建议把 AGENTS.md 中的偏好升级为可执行检查单，每次改动自查：

1. 同一事实在本面板是否只出现一次？跨面板是否有明确主展示位？
2. 新增浮层的 z-index 层级与事件拦截是否已对照既有抽屉/弹窗/提示？
3. 新入口归属哪个对象/层级？是否存在功能等价的旧入口应下线？
4. 首屏新增文字是否 >80 字？规则说明是否有"按需查看"入口？

# 侯景之乱与人物生命周期落地方案

类型：设计提案。范围：546 年历史沙盒、侯景事件链、轻量生命周期修正及相关界面。
状态：**2026-10-14 用户确认后已本地实施；代码与局部规则验证完成，前端待用户人工验收。效果图仍非实机截图。**
核对依据：2026-10-14 本地提交 `66d482b`；[设计侯景之乱事件](chatgpt-conversation://6ace49de-ecd8-83ec-8f09-46dd437af677) 的两轮结论；本地相关代码及三种身份的新局状态探查。

## 1. 建议确认的整体方向

采用“真实规则驱动的七阶段事件链＋轻量生命周期修正”。满足条件就出现机会，不再抽取事件触发概率；玩家和 NPC 按各自权限选择，归附、行军、军饷、内战、围城、俘虏及继承仍由原系统结算。事件可以在安置、改编、议和、平乱等分支自然结束。

高欢死亡不是必要前提。保护者死亡、失去实权、重症引出的交接争议，或真实撤军权／追责冲突，均可动摇侯景处境；康复且矛盾解决可以降温。不存在历史日期处决、必反、必陷建康、必然称帝或自动陈代梁。

前端复用顶部事项、公共决策弹窗、人物详情和纪事。新增一份可回看的事件卷宗，不新增常驻侧栏或“历史点数”。图中布局供确认，正文定义和真实世界数据约束实施。

需要确认的范围分为三项，便于单独调整：

| 项目 | 推荐纳入 | 玩家影响 |
| --- | --- | --- |
| A 事件链和界面 | 通用轻量编排、一条七阶段链、不同身份视角、卷宗 | 可交涉、化解、参与或旁观，同一局中持续存在 |
| B 生命周期 | 年龄风险表、疾病不再到期必愈、医疗只修正病伤风险 | 高龄更替加快；旧档下一次月结算起生效 |
| C 546 年开局基础 | 有来源的侯景军政处境与配套最低守备，独立数据变更 | 让 NPC 侯景具有可行动基础；仅新局初始化，不追补旧档 |

### 546 年开局基础的推荐规格

历史依据只支持侯景有河南军政基础，不能将史书记载的大规模兵数直接塞进当前低规模战役系统。[《梁书》卷五十六](https://zh.wikisource.org/zh-hans/梁書/卷56) 记述其军权、神武病重、召还和请求归附的先后，可支持“保护关系动摇”这一触发方向；疾病、死亡率、军队规模和关系数值均为玩法设定。

建议首轮参数：颍川配置 600 人侯景所统兵团；个人忠诚 70、制度忠诚 60；影响力 80（足以承担一次请求的 20，余量不等于获得起兵资格）。私财保留现值，不额外赠钱。不把侯景伪装成县令，不自动授予十三州；军政基础来自实际统军、追随兵团和驻地。

为避免唯一开局军队造成失衡，同时建议梁、东魏、西魏首都各初始化 600 人中央守备，沿用现有合法统帅席位，缺席则保持空席，由真实任命补齐。共四支起始军队，属于**需确认的新局数据变更**。各来源必须通过兵额、人口、公粮与财政容量校验；不够即报告配置无效，不暗减兵数或增发资源。

初始化在人口、庄园、财政建成之后执行：每个兵团记录来源县域和兵额类型，调用同源人口扣减，粮食从对应公粮转入军粮，军费写明起始财政配置与后续付款账户。存量与在役人口不重复统计。当前颍川可用公共兵额探查为 684／720（随开局身份和庄园分配变化），600 是候选参数，仍须验证全部来源和三国军费承载。

侯景与高欢、高澄的关系只写进有来源的剧本关系配置，具体分数标为游戏参数；不设隐藏的必反特质。其他当前执政者按实际关系判定。若 C 未获确认，A 仍可开发，但应明确“当前新局不保证自然出现侯景主线”，不以运行时送兵补足。

## 3. 七阶段与可达出口

阶段不是任务清单，不向玩家预告未发生章节。标题随真实安置地、国号、人物和首都变化；只有真正公开举兵后称“侯景之乱”。

| 阶段 | 必须成立的事实 | 有权限的选择 | 转入或结束 |
| --- | --- | --- | --- |
| ① 北方生变 | 侯景在世自由、有实际军政基础、有未解冲突；保护者死亡／失权／重症交接争议／真实强制交接至少一项成立 | 侯景交涉、依法交接、请求他国接纳；实际执政者确认待遇或合法调整兵权 | 交涉成立可降温；真实发出请求后进入② |
| ② 纳降安置 | 请求、请求人、接纳政权、道路、军队、权限与预算有效 | 按原案接纳、提出还价、拒绝；侯景接受还价或撤回 | 双方同意后执行归附；拒绝可转投别国；个人归附可直接稳定结案 |
| ③ 归附生疑 | 已归附且仍有军政基础；存在当前欠饷、违反兵权条款、实际安全承诺破坏 | 补足真实军饷、双向重议、按约改编、维持现状 | 争议清零并持续稳定 30 日可结案；新冲突重置稳定观察，不能重复罚旧违约 |
| ④ 举兵向阙 | 实际决定诉诸武力；现有 `civilReason()` 通过 | 君侧清理／夺执政权或合法拥立；忠方选择真实调军、供粮、暂缓 | 生成一次真实内战；提前平乱或议和可跳过围城 |
| ⑤ 首都围城 | 绑定战争的叛军真正形成有效围城 | 守城主官坚守／突围／议降；统帅调度；地方官军粮；普通人保护家业、依法离城 | 解围、撤围、陷落由战争结算；“台城”仅叙事抽象 |
| ⑥ 平乱或挟朝 | 战争、占领、俘虏、执政变更分别出现 | 真实议和、俘虏处置、勤王、政治安排 | 夺城不等于俘帝、全国归属或改朝；地方有抵抗则继续 |
| ⑦ 乱后余波 | 事件实质结束或目标取消 | 查经过；直达赈济、赏赐、俘虏等现有入口 | 汇总已发生损益，不再次扣人口、钱粮或奖励功绩 |

**处理窗口：**③首次正式交涉给 30 日，显示实际截止日和剩余日；这是重新评估期限，不是自动叛乱倒计时。拘捕、处决、战败等真实行动立即产生后果，不受窗口保护。一次问题反复消失／出现不得刷关系奖励。

**梁境地点：**史实寿阳与现有 `shouchun` 场景的映射须在资料说明登记；界面默认显示当前地名“寿春”。不新建 `shouyang`。接纳时地点仍不变，安置需合法地点、职权与真实行程；到达前不显示“已驻寿春”。接纳、授职、调军是分开的动作。

**内应：**首版不以萧正德为强制依赖。当前人物目录检索未找到对应稳定实体，先用既有谋略／支持者事实作可选叙事，不能新增无权限的“开城门”。正式补人物需另有资料、身份与关系定义。

### 不同身份看到什么

| 身份 | 信息与操作边界 |
| --- | --- |
| 侯景 | 自己的威胁、请求、条款、军队及合法政治目标；不替接纳国确认 |
| 实际执政者 | 本国来书与军政处置；君主身份单独不覆盖实际授权 |
| 守城主官／有权统帅／地方官 | 城内议降、所属军令、公粮处分；每项复用具体权限 |
| 普通人物 | 公开军报、驻地危险、依法可用的旅行和家事入口；捐助仅在既有真实命令可用时出现 |
| 外国人物 | 已公开的归附和战争，不获得未暴露密约或尚未发出的打算 |

NPC 使用相同预览、校验和执行入口，传真实 actor，不改 `world.characterId`。满足节点条件即建事件，NPC 的选择可以按既有关系、军权与资源作确定性排序；无合法选项则维持／拒绝并说明，不强行推剧情。玩家负责的决定暂停，NPC 决定不阻塞整局。

## 4. 关键领域改动

### 双方确认条款

原请求保留 `terms`，待议提案增加 proposer、revision、terms、expiresAt、respondent。接纳方改选条款时，主按钮变为“发出还价”，不立即扣接纳费用或转军；对方收到后明确接受／拒绝。第一版同一请求最多一项在途提案，不叠多个相互矛盾的报价。

双方最终确认时重新校验身份、追随兵团、预算、道路和保护战争名额。状态过期／资源不足则全笔失败、保留解释，不留半次扣款。已生效归附的重议亦走同一确认模型；旧条款在新约签订前继续有效。过往违约记录不清除。

### 争议和自动起兵

提取 `currentPactBreaches(world, pact)`，返回当前违约事实和稳定来源键。累计记录只用于纪事；不同月份检查同一持续违约不重复关系惩罚。重议解决兵权争议不等于清偿欠饷。

当前自动 `advancePacts()` 和历史事件不得各起一次兵。为绑定的事件决策提供唯一分发入口；普通归附复用原路径。还须覆盖 `advanceCivilPolitics()` 中的自动 NPC 起兵：同一 actor／政权／真实冲突只能有一个决策所有者，已有战争则绑定而不重建。

改编完成还需明确结清兵权承诺：当前实现把 `reform` 改回 `retain`，会混淆“已完成整合”和“承诺保留独立军权”。建议在原 pact 增加 `integrationCompletedAt`（完成日期元数据），已改编后正常换将不再被误判为违反保留军权；安全和欠饷承诺仍按其有效范围检查。旧档没有完成证据时不补写完成日期、不追罚。

玩家在常规军政界面主动执行合法行动不被事件锁住；事件在行动完成后更新或作废草稿。叛乱的公开名义与国号分离：首轮采用 `PowerArrangement.goal='executive'` 或合法拥立，起兵名号校验不能逼玩家输入新国号。称帝只走后续现有政治条件。

### 勤王和战争结束

“调遣军队”打开选军与真实目标的军令预览，救援首都和进攻叛军基地分别列出。公粮只在现有同地供粮条件下直接转入军队；异地接济走运输，不从任意地方瞬移粮食。

已有忠方接替逻辑不等于所有边界已证明。专测领袖死亡、被俘、换国、失职，以及无人可接替；没有合法代理时按实际军队和和约条件处理，不能悬空绑定旧人。现有自动平乱存在玩家／NPC 分支差异，必须验证无兵、失去基地和被俘时均有可达出口；仅在失败用例证明必要处修复。

## 5. 状态、命令与存档

新增轻量 TypeScript 编排，不造脚本语言或可视化编辑器。

| 数据 | 类别与持有者 | 单位／范围 | 用途及约束 |
| --- | --- | --- | --- |
| `HistoricalState.version`、definitionVersion | 元数据，World／实例 | 正整数 | 数据校验、迁移和文案版本 |
| id、definitionId、occurrence | 元数据，实例 | 稳定键 | 同一触发事实去重；再度危机需新事实，不能读档再触发 |
| phase、status、phaseSince、resolvedAt | 状态／日期，实例 | 枚举、世界日 | 分支与纪事；没有虚拟百分比进度 |
| actors、refs | 实体引用，实例 | 人物／pact／war／site ID | 只指向真实实体，不复制兵力、资源或实时控制权 |
| decision id、revision、actor、option | 待决状态，实例 | 稳定键与合法选项 | 旧草稿、离任、重复点击和越权拒绝 |
| handlingDue、stableSince | 日期状态，实例 | 世界日或空 | 30 日交涉／观察，仅到期评估；不是资源 |
| milestones | 已发生事实，实例 | 稳定来源键、日、摘要、可见范围 | 不依赖短日志；不携带可重放资源效果 |
| appliedEffects／决策回执 | 幂等元数据 | 来源键集合 | 仅成功后记录；与资源变化同事务提交 |
| `currentBreaches`、界面预估 | 派生值，不另存数值账 | 从 pact／军队／权限现算 | 不重复累积或结算 |

建议文件：`src/core/historicalEvents.ts`（调度和接口）、`historicalEventState.ts`（类型）、`historicalEventSave.ts`（校验迁移）、`historicalEvents/houJing.ts`（条件和分支），史料与展示文案放 `src/data/historicalEvents/`。按现有职责切分，不预建多余框架。

提交形如 `{type:'historicalEvent', instanceId, decisionId, revision, optionId, selection}`。selection 仅含选军、地点或方案的实体 ID，服务端规则重算所有成本与效果，拒绝直接传兵力、奖励、国号变更效果等。普通实体详情操作仍提交原命令。

在成功命令和每日模拟全部结算完成后检查。单次检查每实例最多新建一个待决；已发生事实可补记，但不能瞬间连播七章。自动归附和叛乱的决策拦截设在各自执行之前，事后观察不足以防止抢先执行。

worker 的 init、load、import、resume、step、speed 与加速日循环共用历史待决查询。打开人物或地图查看不等于办结，待决仍保留；玩家失权时重新路由至新责任人。合法拒绝、维持现状是完成决策，不能要求玩家必须执行高成本选项才能继续。

**旧档：**缺少历史状态则初始化空编排，自迁入日起观察。已有归附、内战、围城可绑定明确来源；过去缺失经过显示“从当前局势开始记录”，不合成历史选择。缺关键人物、断引用、战争结束时分别暂停节点、降级为纪事或终止，并保留原因。归附及战争记录会被清理，结案时必须写入必要事实快照；不能依靠以后还查得到原记录。禁止补兵、补影响力、追罚、追死；存档往返保持决定和通知去重。

秘密里程碑带参与者／政权范围及公开日，UI 和查询同时裁剪。已结束记录保留必要事实，限制文本长度与节点数；不把每一天的围城快照塞入存档。

## 6. 人物生命周期的轻量修正

不新增寿命、指定卒年、复杂器官、失能摄政、瘟疫或夭折系统。保留死亡清理、家业继承和公共继任。

### 建议参数

| 年龄 | 基础年死亡概率 | 换算月概率约 |
| --- | --- | --- |
| 16—39 | 0.3% | 0.0250% |
| 40—49 | 1% | 0.0837% |
| 50—59 | 3% | 0.2535% |
| 60—69 | 8% | 0.6924% |
| 70—79 | 18% | 1.6402% |
| 80—89 | 35% | 3.5262% |
| 90 及以上 | 55% | 6.4377% |

这些是首轮游戏节奏参数，不是南北朝人口统计。16 岁以下保留现规则。首版用明确分段表，不暗加平滑曲线；换算统一为 `1 - (1 - annualRisk) ** (1 / 12)`。

```text
年龄风险 = 月概率 ×（强健体质 ? 0.9 : 1）
病伤风险 = max(月初重症 ? 0.04 : 0, max(0, 25 - 月初健康) × 0.003)
病伤风险 *=（有效延医 ? 0.6 : 1）×（强健体质 ? 0.8 : 1）
最终月风险 = 1 - (1 - 年龄风险) × (1 - 病伤风险)
```

其中强健的年龄系数 0.9 为本方案建议，保留小幅长寿优势；0.04 重症风险沿参考会话起始建议。所有概率限定在 [0,1]，未知年龄不静默当零岁，沿用已登记约龄，否则报数据缺口。

结算顺序：月度幂等检查 → 合法自动照料及其支付 → 固定月初病情／健康快照 → 一次死亡判定 → 存活者推进病情／伤情／恢复。当月新恶化不再回头重抽重症风险。健康已经为零保留原死亡规则；若本月病伤把健康耗尽，仍按健康耗尽死亡，界面不能承诺必有一个月保护期。死因依实际触发分量区分年龄／病伤，不因偶患轻症就一律记病逝。

四种疾病保留当前基础康复、恶化、健康损耗参数。删除“病程到期直接清除”；首轮按严重程度对基础康复率乘 1／0.65／0.35，再加延医 0.25、强健 0.08。仅轻症保留每 60 日 +0.08 的恢复趋势，最多 +0.16；总概率上限 0.95。重症不无限吃时间红利。康复／恶化互斥：未康复时才按原恶化系数抽一次，否则持续并结算损耗。原最长病程转成“病情迁延”的说明依据，月结算仍为唯一重评，不新增另一轮抽签。

健康上限公式暂不改。延医价格 30 私财、90 日照料、自动延医 90 钱额度不预扣，以及休养真实限制均沿用。NPC 自动延医继续用本人私财；核对其与月风险的调用顺序，不能因执行次序让 NPC 刚应触发的照料晚一轮才生效。

健康通知只报首次进入重症、健康跨入危险区、康复及高龄未安排继任等状态变化。高龄提醒建议 70 岁起且确有可办继任事项；状态不变不逐月弹窗，不通知所有陌生 NPC。公共继任、家业继任分别显示，休养不自动交出国家权力。

## 7. 前端效果和交互约束

效果图见 [美术目标与提示词](../art-direction/hou-jing-event/README.md)。

| 图 | 页面 | 要确认的变化 |
| --- | --- | --- |
| 01 | 河南来书／纳降裁决 | 人物与驻地、三方案单选、真实确定后果、改条款需对方确认、唯一执行区 |
| 02 左 | 降将安置卷宗 | 当前争议、已发生经过、处理期限、紧凑行动、顶部旗帜 |
| 02 右 | 建康告急 | 围城、粮情、援軍真实状态；按地方官身份限制操作 |
| 03 左 | 人物身体与安排 | 年龄、病情、照料分开，直达现有养护／继任／交接 |
| 03 右 | 病榻议事 | 重症引出的交接选择；进入安排不等于已移交权力 |

战后采用同一卷宗“经过”页：顶部结果印记“改编安定／议和收场／围城解除／起兵失败”等，列已发生的人物、城市、财政影响，底部只有真实善后入口。不新增结算领奖窗口。健康康复用现有纯通知模板；这两类复用布局，文案和状态仍纳入人工验收。

具体规则：

- 事件在前期使用“河南来书”“降将安置”“寿春疑云”等当下标题，未来节点不可见。玩家无权知道的原因不通过禁用提示泄漏。
- 宽屏弹窗目标约 1100—1280 CSS 像素，正文局部滚动，底部确认常驻；紧凑屏以现有弹窗布局降级，不缩小点击区或裁字。
- 标题插画控制在窗口上部约五分之一，肖像、地点、行动使用真实实体入口。不迁移生成的人像去覆盖现有角色肖像。
- 纳降原案选中时显示“确认按原案接纳”；改选显示“发出还价”；等待对方时没有可用的“已接纳”假状态。费用、付款账户、战争后果随所选方案同步。
- 决策弹窗无“知道了／关闭”；进入子详情可返回原决定。普通详情／行动草稿支持 Escape 和焦点返回；顶层强制待决的 Escape 不办结、不解除时间锁。
- 选卡只改草稿，最终提交前复核；重复点击、跨对象、身份变化清除失效草稿。错误保留在当前状态区。
- 旗帜不显示 tooltip，固定宽度区内与现有战争／事项去重，战争旗帜仍在前。若已有对应战争旗帜，历史入口挂在战争详情，不多挂同一场围城。
- 不做“叛乱概率 73%”、没有真实期限的倒计时、未来完整章节表或寿命进度条。健康数值不是剩余寿命。
- 深色嵌入框显式设定自身 `--dialog-ink`／`--dialog-muted`；纸面警告用深色，选中、禁用、焦点三种状态分别定义。
- 复用 `PauseDialog`、`EventDecision`、`ActionDialog`、`OngoingFlags`、`LifeDetails`；增加历史内容组件，纪事中接入持久卷宗入口。需要参数的行动全部进入原行动弹窗。
- 不新增地图地形或模型。定位按钮仅用户点击时移动视角；公开军情复用现有地图标记，私人健康和密谋不放公开地图。

## 8. 实施顺序与局部验收

确认整体方向后按四个独立阶段实施，各阶段保留本地检查点和对应记录；不创建分支、不推送、不部署。

| 阶段 | 交付与依赖 | 放行条件 |
| --- | --- | --- |
| P1 生命周期 | 风险纯函数、疾病顺序、提醒、原继承回归 | 概率换算、快照、月结算幂等、旧档不追死、死亡清理通过 |
| P2 数据与通用编排 | 获确认的开局配置、状态／迁移、条款双向确认、共享争议查询 | 新局兵源守恒；同身份事实；旧档不增发；重复请求不重复效果 |
| P3 七阶段和领域接缝 | 条件、NPC 分发、政治目标、围城和结束出口、长期里程碑 | 下述分支用确定性小世界局部测试覆盖 |
| P4 界面 | 按已确认效果图接入所有身份和状态 | 类型／构建／非 UI 检查通过后交用户人工验收 |

P1 可独立交付，但不是 A 的替代品；完整方案完成须包括 P2—P4。未确认 C 时不得声称完成新局自然可达性。

重点局部用例：

1. 保护者健康且无冲突不触发；保护者重症＋真实冲突触发；康复并解决矛盾可降温；不按历史年份强杀。
2. 侯景已故／被俘、接纳国终止、请求人换国，作废对应待决；后继玩家不重开事件。
3. 条款修改必须双方确认；和平武装接纳恰好生成一次保护战争；预算不足失败无半扣。
4. 欠饷归零解除当前争议，历史违约保留；连续检查不重复降关系；完成改编真能稳定结案。
5. 调度与普通 NPC 自动逻辑同日竞争，只能一场战争；已有内战绑定或报告冲突，不新开平行世界。
6. 起兵检查失败无部队／钱粮赠送；政治目标不自动变改朝；无兵、失去基地、被俘、议和均可结束。
7. 实际城域阵营决定占领；皇帝离城不被俘；首都陷落但忠军仍在时继续；忠方责任人失效可接替。
8. 选援军实际开往所选目标；异地输粮包含路线和损耗；普通人不能提交国家决定。
9. 重复提交、同日复查、保存读回、导入、加速均不漏暂停或重复效果；秘密查询无越权。
10. 事件结束仅汇总损失；旧源记录清理后卷宗仍可读；遗漏史段不补造。
11. 年龄段边界、年/月换算、医疗不改年龄风险、无到期必愈；同版本同种子一致，跨版本不承诺相同未来随机序列。
12. 首次重症和康复提醒去重；死亡沿原官职、军队、婚姻、财产、继承清理链闭环。

实施验证使用相关测试文件及新增局部测试，代码每阶段保留 `npm run build`。不默认全量 `npm test`，不跑长局或完整游戏回归；没有几十年全局平衡证明，首轮风险表须后续体验反馈。UI 仅用户人工验收，不使用浏览器自动化或截图比对。

影响关系实施时更新既有数值审计；类型声明变化后运行字段清单脚本。当前只是提案，不提前把新公式写成现行机制。

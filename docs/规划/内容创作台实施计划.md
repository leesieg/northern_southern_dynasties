# 内容创作台实施计划

类型：分阶段实施计划。
范围：落实[完整设计方案](内容创作台设计方案.md)中的内容底座、人机共用编辑服务和四类编辑器。
状态：2026-10-14 用户已授权按方案开始实施，保留既有玩法和旧档兼容，执行必要局部验证，暂不推送或部署。阶段 1 首批底座已实现并完成局部验证，阶段 1 完整门槛尚未满足；阶段 2—6 尚未开始，UI 未验收。
依据：本地 `26addad` 的定向代码抽查、项目规则及本轮认可的设计方向；不是完整工作量估算。

## 1. 推进原则与交付状态

按“可运行内容闭环”交付，每阶段同时明确数据、操作、界面、兼容和验证。CLI 与界面共用能力，AI 无界面制作能力不后补。优先已有技术，不先拆仓库，不并行开工四个完整编辑器。

| 1 内容加载与隔离底座 | 官方内容快照、实例注册表、开局入口、存档适配与隔离试玩 | 阶段 0＋实施授权 | 首批完成：只读目录、地图缓存、共用运行器与隔离试玩；完整包与世界注入待完成 |
| 2 人机共同编辑最小闭环 | 编辑服务、CLI、变更审阅、基本人物与剧本编辑 | 阶段 1 | 未开始 |
| 3 事件制作闭环 | 条件行动注册、结构化编辑、调试和短事件链 | 阶段 2 | 未开始 |

## 2. 阶段 0：文档与预期效果

交付完整设计、本文、地图／事件／人物／剧本四类效果图、图册说明及生成提示词，更新文档总索引。效果图落于 `docs/art-direction/content-studio/`，不进入运行资产目录。

阶段 0 检查文档互链、图片存在性、状态声明和 `git diff --check`，未执行构建、游戏测试或浏览器 UI 验收。用户人工确认布局、信息层级、修改范围、AI 提案审阅和试玩入口；之后用户已另行明确授权实施，见本文开篇和当前进度。

## 3. 阶段 1：内容加载与隔离底座

### 工作包

1. 定向列出静态内容读取、初始化、模块缓存和迁移依赖，区分必须注入与可保留适配；建立 Schema 与内容编译器的最小输入输出合同。
2. 提取官方 546 内容包或由现有源数据可重复编译的官方包；保持稳定 ID 和原有玩法参数。编译顺序、依赖锁和摘要有确定性。
3. 建立按实例绑定的注册表及寻路缓存，让剧本初始化接收完整内容与日期；禁止先创建默认世界再局部覆盖。
4. 分离模拟与存储，提供不接触正式存档的试玩适配器；解析旧档与新档的内容绑定关系。
5. 形成编辑服务与变更合同的库级接口草案，供下一阶段复用，避免 UI 先写独立修改逻辑。

主要涉及的现有位置：`src/data/scripts.ts`、`src/data/scenario.ts`、`src/core/world.ts`、`src/core/historicalStart.ts`、`src/core/personRegistry.ts`、`src/core/save.ts`、`src/core/contentMigration.ts`、`src/worker/simulation.ts`。实际修改范围以依赖检查为准，不在计划阶段预设全量重写。

### 完成门槛

- 官方包可以经新入口开局，选定固定种子与短命令序列的关键世界结果与原基线一致；允许明确登记的序列化差异。
- 两个内容实例的地点、人物和路径缓存互不串用；缺包、错误摘要和不兼容版本明确报错。
- 代表性旧档通过专属适配器恢复；原档不被覆盖，其他包不被补入官方内容。
- 试玩的创建、推进、行动、退出及测试存档往返不写正式存储或线上保存端点。
- 对直接改动执行局部测试和 `npm run build`；没有 UI 自动验收或长局测试。

回退：保留旧读取适配器及原始存档样本；新链路未通过门槛时不设为正式入口。需要双入口比较时使用显式开发入口，不能静默回退并伪装新内容加载成功。

## 4. 阶段 2：人机共同编辑最小闭环

### 工作包

1. 本地工作区服务负责目录范围、修订、暂存写入、原子切换、回执与恢复；UI 和 CLI 调用同一服务。
2. 实现能力发现、实体搜索／读取、引用查询、提案、预检、应用、撤销与草稿备份。AI 通过 CLI 或结构化适配调用；MCP 包装不作为第一天前置。
3. 变更集实现基础修订与原值前置检查、幂等键、授权范围、冲突报告；人工提案与 AI 提案走同一逻辑。
4. 工作台外壳、问题面板、版本与范围提示、差异审阅；右侧先支持外部 AI 提案，不依赖内置聊天模型。
5. 人物基础档案、关系、剧本状态，以及剧本复制、日期、人物政权配置、基础资源和可玩人物；共享定义／剧本覆盖明确区分。

### 完成门槛

- 人类复制剧本、新增人物并配置家族、任职和资源，局部校验后能隔离开局。
- 无界面工具完成相同操作，读取相同有效值；UI 展示工具产生的提案和完整前后差异。
- 两个编辑者基于同一旧修订提交时，后一个收到冲突；重复提交返回原回执；写入中断能恢复到完整修订。
- 撤销有后续依赖时不覆盖后来修改，删除被引用实体不留下悬空引用。
- 未授权共享库写入、越界路径、未知操作被服务拒绝；未知字段和类型错误定位到字段。
- 局部接口／文件测试及构建通过，UI 入口交用户人工验收。

范围控制：此阶段用已有地图和现有事件；不因人物家谱顺带做任意关系图编辑器。AI 自动应用仅开放用户明确授权范围，导出及发布权限不默认继承。

## 5. 阶段 3：事件制作闭环

### 工作包

1. 定义有限条件、角色选择器、行动能力与参数 Schema；先盘点真实可调用规则，再决定首批选项。
2. 事件定义、实例状态和展示投影分离；注册现有侯景专用处理器，保留原行为。
3. 实现条件表单、阶段／选项、NPC 策略、超时异常收尾及逐条件诊断；后果使用真实规则和效果去重。
4. 通过一条简单政务事件和一条短分支链验证配置；AI 生成受支持字段及修复提案，人类能修改同一内容。
5. 局部测试场景保存内容版本、种子、初态、命令与推进预算，结果反向定位作者字段。

### 完成门槛

- 新事件不修改核心代码即可触发、选择、结算和结束；正式游戏组件预览来自编译后同一配置。
- 覆盖正常完成、无合法选项、执行者死亡／离任、对象失效、超时，以及规则明确支持的取消；不能取消的操作说明不可取消原因。
- 重复点击、保存重读、重复同日推进不重复扣款、奖励或产生战争；失败的复合后果不提交部分状态。
- NPC 只执行有资格的选项，不替玩家决策；未支持行动明确拒绝，不能用脚本兜底。
- 诊断准确区分结构已通过、行为未执行、预算耗尽和真正通过。
- 对注册和迁移影响执行局部事件测试及构建，UI 人工验收。

阶段里程碑：人类创建人物，AI 为短事件提出变更，人类审阅应用，完成局部试玩。这是早期人机闭环，但不是第二剧本完整验收的替代。

## 6. 阶段 4：战略地图与第二剧本

### 工作包

1. 共享地理／当前剧本局势模式；地点、道路、区划父子、法理归属和实际控制独立编辑。
2. 地点移动与道路变更重建实例派生数据，显示路径与行程影响；边界生成先预览，保留手工成果与来源。
3. 补齐经济军务开局资源分配、驻军与统帅、外交及事件包组装，生成待复核清单。
4. 完成资产和资料清单、必要文件校验、精确依赖锁、可运行包导出与导入。
5. 制作明确标为验收用途的第二剧本，独立内容环境加载，验证对官方包的隔离。

### 完成门槛

完整验收序列：复制官方剧本→新增人物／家族／职位→配置有资源来源的军队→修改一个地区的控制和一条道路→新增带选择与收尾的事件→静态校验→局部隔离试玩→测试存档往返→导出→另一个本地环境导入开局。

- 全流程内容作者不修改 `src/core`；新增底层机制需求单独登记，不伪装为配置能力。
- 原剧本和已开始的实例保持原内容版本；新地图不改变旧旅程。
- 接壤、道路通达、行政关系分别正确；控制权变化不自动改变行政上级或扩张至第三国。
- 军队来源、人口、公私资金与补给口径可追踪，没有重复计入。
- 包不依赖作者机器上的隐式文件；缺依赖和错误摘要按预期报错。
- 局部地理、初始化、资源和包往返测试及构建通过，用户人工验收四类编辑器。

不含：手绘复杂边界、地形雕刻、模型制作和公开发布。

## 7. 阶段 5 与后续

阶段 5 针对实际制作问题补充恢复、旧档兼容、跨包冲突、导入安全与内容作者说明；检查大列表分页、延迟肖像、缓存上限和可取消操作。性能记录数据规模和环境，不先承诺未经测量的耗时指标。

交付物是可安装／运行的本地作者入口、示例内容包、操作说明、已知限制与支持能力表。选择已有最小测试集合复核共享基础影响；未获用户明确要求不执行长局或完整游戏回归。发布或推送依然需独立明确授权；“部署并推送”按项目规则委派指定模型代理，不能从实施授权推定。

阶段 6 仅按作者实际需求立项：流程图拖拽、手工边界、GIS 导入、更强批量编辑、嵌入式 AI 会话和更丰富规则注册。每项都沿用现有源数据及编辑服务，不建立第二份平行数据模型。在线协同与模组市场另行评估。

## 9. 每阶段收口与回退边界

实施前检查工作区差异并保留本地检查点，保护已有未提交资料；未经明确授权不创建分支／worktree。改动按主题提交和记录实际检查，不推送、不部署、不写入 `trusted/`。

每阶段交付说明只列：已完成能力、实际验证、待人工验收、已知限制、下一阶段依赖。规则影响变化就近更新数值影响审计，字段声明变化再重建字段清单；纯编辑 UI 或本文规划不触发无关审计重写。

失败只回退本阶段新入口／修订，不改写正式存档，不删除作者输入，不以默认官方世界替代无法加载的新包。已经发布或跨版本使用的内容若需迁移，必须提供明确兼容说明与原始版本保留路径。

进入下一阶段的条件是当前技术门槛已通过、需要的人工验收状态已如实记录，并且用户的实施授权覆盖下一阶段；文档认可、沉默或查看效果图不能作为新增授权。

## 10. 当前实现入口与验证（2026-10-14）

### 可直接使用

仓库根目录执行，工具仅在本地运行，不启动 HTTP／WebSocket 服务：

```bash
npm run content:inspect
npm run content:inspect -- find person 萧
npm run content:inspect -- find site 建康
npm run content:inspect -- route jiankang ye
npm run content:preview -- xiao-gang 1
```

查询输出官方目录身份、SHA-256 摘要和对象；路线仅表示地理通达，不代替当前世界的国境／外交权限。当前目录含 113 个地点、150 条道路（包含旧行程保留边）、325 个可玩人物定义、325 个关系人物、286 个家族、346 个家谱人物和一个剧本；这些集合有重叠，不能相加为独立人物总数。

试玩命令参数为人物 ID 与推进天数（0—7）；默认萧纲、0 日。使用真实沙盒开局及规则，遇到待决事件停止并返回 `paused`，不是自动替玩家选择。输出请求／实际推进天数、随机种子和暂停原因；正常完成退出码 0、参数／执行错误 1、待玩家处理导致未完成 2。这个固定小预算入口不授权长局测试。

程序入口：`src/worker/previewSession.ts` 的 `createPreviewSession(onReply)` 提供同一 `Request` 协议的 `dispatch` 和显式 `tick`，请求与回复均复制隔离；内存存储最多保留三个自动槽、一个手动槽和一个前局槽。会话无后台定时器，丢弃会话即不再运行。没有接入正式 UI，也不导入或修改用户实际存档。

### 实际验证

- 新增 14 项测试通过：目录与缓存隔离、非法引用、亲缘环、旧道路保留、存储限额、写入失败、两个试玩会话隔离、正式初始化等价、重复命令和未知剧本拒绝。
- 选定正式 Worker 回归 5 项、旧档／存储／路径回归 9 项通过，共 28 项局部测试；未运行全量、模拟年或长局回归。
- 对照改动前 `26addad` 的原寻路实现，113 个地点的 12,769 对路径及 150 条道路的预约时长结果相同。该检查只覆盖路径算法，不证明整套玩法完全等价。
- TypeScript 与 `npm run build` 通过，854 项发布资源校验通过；保留构建分包体积提示。CLI 官方目录查询和萧纲推进一日实际运行成功，修正了工具最初尝试启动热更新端口的问题。
- 没有修改存档封装版本、官方内容版本、既有迁移或数值规则；已验证范围含缺少剧本字段的旧档恢复、官方历史开局军队回读和存储失败回滚。没有读取用户实际旧档，不能据此声称所有历史存档都已验收。

本地检查点及日志位于 `.cache/content-studio/`，不进入发布或 Git：设计快照、开始时工作区差异、局部测试日志、路线等价结果及构建日志。首次基线测试筛选意外匹配 suite 名，已中止，未计入通过结果；后续明确选定单项运行。

2. 规则、资产、内容依赖和旧档锁定形成可加载包；目录摘要目前不能当成完整内容锁。

4. 门槛满足后进入草稿事务、版本冲突、审阅与人物／剧本 UI；不以只读目录替代编辑功能。

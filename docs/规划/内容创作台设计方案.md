## 1. 产品定位与成功标准

将《风云南北朝》逐步组织成“可复用模拟内核＋可独立加载的内容包＋统一内容创作台”。首期服务于现有人物驱动历史策略游戏，不承诺制作任意类型游戏。保留现有项目与技术栈，不以拆仓库、换引擎、重写全部核心为前提。

人类通过地图、表单、关系视图和预览制作内容；AI 通过结构化工具发现字段、查询实体、提出变更、检查问题并在授权范围内应用。两者共用权威内容、编辑服务和校验规则。没有 AI 也能完成全部基础内容制作，没有浏览器界面也能通过工具完成受支持的内容操作。

首个完整成果是制作第二个可运行剧本：复制官方 546 剧本，增加人物与任职，配置有来源的军队和资源，修改一处局势与道路，添加有分支且可结束的事件，校验、隔离试玩、导出并在另一个本地内容环境重载；内容作者不修改 `src/core`。这可以是明确标为架空的验收剧本，不冒充已考订的另一历史年份。

### 支持边界

| 扩展 | 支持方式 |
| --- | --- |
| 人物、家族、传记、已有特质、同机制下的新剧本与事件 | 内容配置和资源引用 |
| 地点、道路、行政隶属、初始控制、既有建筑兵种参数、已有制度组合 | 编辑器配置，受当前内核能力约束 |
| 新经济算法、全新战斗方式、全新制度运作 | 开发者增加可信代码并注册能力，再提供配置入口 |
| 地形雕刻、模型建造、骨骼动画 | 继续使用外部资产工具；创作台负责导入、引用和预览 |
| 模组市场、在线多人协同、任意脚本插件、自动公开发布 | 不进入首期 |

本期“人机协作”指同一项目中的可审阅变更与版本冲突处理，不要求多人实时光标或分布式协作系统。

## 2. 当前基础与改造原因

| 已抽查位置 | 当前事实 | 设计要求 |
| --- | --- | --- |
| `src/data/scripts.ts` | 单一 `three-realms-546` 目录，主要包含菜单元数据 | 剧本提供完整初始世界输入，菜单读取同一配置 |
| `src/core/world.ts` | 静态读取地点道路，模块级寻路表，默认世界和三国初始化 | 按内容实例建缓存，初始化不能先造默认世界再零散覆盖 |
| `src/core/personRegistry.ts` | 查询入口已统一，底层仍依赖静态人物、关系和家族名录 | 保留调用接口，逐步替换为当前实例的注册表 |
| `src/core/historicalEvents.ts` | 侯景事件已有阶段和效果记录，调用归附、内战、权力行动 | 保留真实规则，先接注册及诊断，再渐进迁移专用逻辑 |
| `src/core/save.ts` | 按全局内容版本与当前地点等校验 | 先解析存档绑定的内容集，再执行适用迁移与校验 |
| `src/worker/simulation.ts` | 新局、推进和命令与正式保存直接关联 | 抽出存储边界，试玩使用独立适配器 |

正式地图沿用已获授权的 Three.js 渲染链路和真实地理投影，不把旧方案中“MapLibre＋Three.js”描述当作重新切换渲染方案的依据。编辑器添加选择、道路和区划辅助层，不重建一套平行地理事实。

## 3. 架构与权威边界

```text
人类界面                 CLI / AI 工具（后续 MCP 适配）
    └─────────────────┬──────────────────┘
                  编辑服务
      查询 / Schema / 引用 / 变更集 / 校验 / 撤销
                      ↓
              版本化草稿与内容源文件
                      ↓
         解析依赖 / 编译 / 派生资源 / 内容锁定
                      ↓
             实例专属的只读 ContentRegistry
                      ↓
                 同一模拟内核
                 ↙          ↘
       正常游戏＋正式存储     隔离试玩＋临时存储
```

- **编辑命令**修改内容定义或开局配置，例如设置某县初始人口；**游戏行动**改变运行世界，例如征募扣减实际来源人口。两个权限域分别建模，事件不能调用作者编辑权限。
- 注册表、寻路图、资产解析、随机源及迁移上下文绑定实例和内容摘要，不使用全局可变“当前包”。两个不同剧本的预览和旧档检查可以共存。
- 预览复用真实查询及行动规则；涉及执行的测试在世界副本内完成，不另写一套近似收益公式。
- 源文件是可维护内容的权威，编译产物是可重建快照；运行世界不反向覆盖源内容。试玩发现问题后必须通过显式编辑命令修改草稿。

## 4. 数据模型与内容包

### 4.1 三类数据

| 层次 | 人物示例 | 地图示例 | 生命周期 |
| --- | --- | --- | --- |
| 共享定义 | 稳定 ID、姓名、出生资料、家族、传记、外观模板 | 地点坐标、地理道路、基础资产 | 多剧本复用，变更需查看引用影响 |
| 剧本初始状态 | 生死状态、所在地、效忠、官职、私财 | 日期对应的行政关系、控制、人口、驻军 | 当前剧本覆盖，显式标记继承与覆盖 |
| 运行状态 | 任免、成长、婚育、旅行、受伤 | 占领、建设、运输、战争损耗 | 本局保存，绑定精确内容集 |

史料死亡日期属于资料，不等于强制死亡规则；开局时的生死状态须与日期和设定一致。年龄从出生资料和剧本日期推导，未知日期保留未知或区间，不伪造精确年龄。多个年份共用人物时，只修改当前剧本任职不改变共享身份。

派生值只读或明确提供“修改来源”入口，兼容镜像不允许独立双向写入。新数值须登记存量／状态／派生／进度／元数据，说明持有者、单位、范围、来源与消费者；具体字段清单在实施时随权威 Schema 生成，不在本提案复制当前全量类型。

### 4.2 拟议包结构

```text
content/<package-id>/
  manifest.json
  maps/  people/  families/  realms/  events/
  scenarios/<scenario-id>/
  assets/  sources/
```

`manifest` 至少包含 `packageId`、`version`、`schemaVersion`、内核兼容范围、依赖、提供的剧本、资产及许可清单。导出时附内容锁定清单，记录依赖的精确版本、文件摘要和编译器版本。内容摘要覆盖规范化源数据与资源清单，不能只依赖易重写的版本字符串。

首期仅支持基础包＋一个剧本＋可选事件扩展。依赖须无环，缺包和同字段冲突明确报错，不用加载顺序默默覆盖。覆盖项指向明确的实体及字段；区分未覆盖、显式空值和恢复继承，删除操作保留引用诊断。

保留现有官方 ID，不批量重命名。新建实体采用包命名空间下的稳定 ID，名称可变而引用不变；复制实体生成新 ID，并显示哪些关系保留、哪些需要重绑。跨包引用必须声明依赖，导出不得依赖工作区中未打包的隐式数据。

资产通过 ID 引用，记录类型、摘要、作者、来源、许可和适用用途，运行路径在编译时解析。作者设定、模拟参数、史料记载、推定和待核验分开标记；AI 生成文本默认是待核验草稿，不能自动变成史料来源。

## 5. 人类与 AI 共用的编辑服务

### 5.1 能力合同

下列是拟议能力名，不是当前已存在的 API；先建立库接口与本地 CLI，再按需要加 MCP，避免维护多套规则。

| 能力 | 关键输入 | 关键输出 |
| --- | --- | --- |
| `describeCapabilities` / `getSchema` | 内核、包与实体类型 | 支持的操作、参数、范围、单位、引用类型及限制 |
| `searchEntities` / `getEntity` | 项目、剧本、过滤条件、分页或 ID | 内容版本、继承来源、有效值和可编辑字段 |
| `findReferences` | 实体或资产 ID | 引用位置、所属剧本和删除／共享修改影响 |
| `proposeChanges` | 基础版本、作用域、操作及理由 | 未应用的变更集与结构化差异 |
| `validateChanges` | 变更集与目标快照 | 错误、警告、影响、待验证项 |
| `applyChanges` | 变更集、预期版本、授权范围、幂等键 | 新版本、回执、撤销依据，或完整冲突报告 |
| `revertChanges` | 已应用变更、当前版本 | 经过冲突预检的新反向变更集 |
| `runScenarioCheck` | 内容摘要、场景、种子、局部推进预算 | 可复现报告、失败步骤、运行结束原因 |
| `exportPackage` | 已校验版本、目标格式、资源选择 | 导出文件、依赖锁定、检查摘要 |

返回结构化结果，同时提供可读说明。诊断包含 `code`、`severity`、`entityId`、`fieldPath`、消息、相关引用、可选修复建议及检查版本；修复建议仍走变更流程。没有支持的能力时返回明确“不支持”，AI 不得以任意脚本补洞。

### 5.2 变更集与并发

变更集至少记录：`changeSetId`、项目与包、`baseRevision`、作用域、作者类型、人类任务授权引用、操作列表、预期原值、理由、来源、校验版本和状态。操作采用受约束的实体创建／字段更新／关系修改／删除，不开放任意路径文件写入。

状态为“提案→预检→待应用→已应用”，另有冲突、拒绝与失效；应用不代表试玩通过或内容已经发布。AI 可保存提案供人类接手，人类也能继续修改 AI 草稿。

应用前在服务端／本地写入服务中重新校验权限、版本、引用和约束。首期采用项目草稿修订号的乐观锁；版本变化后即使修改字段不同，也先刷新、重算差异并重新校验，不默默自动合并。之后可按实际需要增加字段级无冲突重放。

一组相关操作先在候选快照中完整执行和校验，再原子提交。多文件写入使用暂存修订目录、完成清单和原子切换的活动修订指针；不能把逐个文件 rename 当成整个事务。导出源目录时同样先完整生成再切换。失败不留下半组人物、关系或扣款。

相同幂等键和相同请求返回原回执；键相同但内容不同报错。幂等回执与草稿修订一起持久化。撤销通过反向变更产生新修订，遇到后续依赖则阻止或要求连同依赖一起处理，不回滚并覆盖他人后来修改。

### 5.3 授权与 AI 上下文

默认 AI 可查询当前项目授权范围并生成提案。用户可以明确授权某些实体、字段和次数／任务期限内自动应用；服务端检查范围，不能只相信模型提示。共享库修改、删除、导出和公开发布具有独立权限。批准设计方案不等于批准实施或发布。

AI 面板显示当前对象、修改范围、引用上下文、任务目标、提案及检查状态；可折叠，也可以完全不用。先向 AI 提供选中实体、必要 Schema 和引用摘要，按需分页扩展，避免每次读入整个内容包。外部资料只作为内容，不作为操作指令；工作区授权不自动包含其他目录或账号资料。

首期外部 AI 可通过本地 CLI 工作，不要求创作台内置模型供应商。嵌入式对话接入后置；效果图右侧首先可以作为外部 AI 提案收件箱。模型密钥留在运行配置或系统凭据中，不进入内容包、变更日志或 Git。

## 6. 统一工作台与四个编辑器

### 6.1 工作台外壳

顶部常显项目、内容包、剧本日期、草稿版本和保存状态；撤销、校验、隔离试玩、导出是不同动作。左侧为剧本／地图／人物／事件／政权／资产，旁边为可搜索的对象目录；中间编辑；右侧按需切换属性、引用、变更或 AI 提案；底部问题与局部试玩日志可收起。

对象切换保留已保存草稿和返回位置，未提交表单显示真实状态。错误允许保存草稿，但禁止产生标为可运行的导出包；另提供明确标为未校验的项目草稿备份。所有差异预览显示“当前草稿／提案预览”，未应用内容不伪装成已保存。生成图片只约束布局方向，细节冲突以本文和项目规则为准。

目标为桌面键鼠；大屏多栏，较窄窗口把右侧收为可切换面板，长名单和属性分别滚动，不把文字和点击区缩到不可用。不要求首期手机完整制作。支持键盘导航、焦点、撤销重做、快捷搜索；状态不能仅靠颜色表达。

### 6.2 人物编辑器

人物目录提供姓名／ID 搜索，文化、家族、剧本内外、生死和问题筛选；行内显示小肖像、姓名、家族和本剧本身份。跨列表选择同一 ID 打开同一档案，不维护第二份人物库。

| 页签 | 内容与操作 | 关键限制 |
| --- | --- | --- |
| 基本档案 | 姓名、出生资料、文化、家族、传记、来源 | 明确共享定义；资料不确定性原样保留 |
| 能力特质 | 基础能力、已有特质、冲突解释、有效值分解 | 派生加成不可重复输入；未知机制不能只写效果文案 |
| 家族关系 | 父母、配偶、子女及关系图 | 引用同一人物；防亲缘循环和不合理日期；史料／作者设定分开 |
| 剧本状态 | 存活、所在地、效忠、职位、私财、庄园、可玩资格 | 默认只改当前剧本；地方公库与个人钱包分开 |
| 游戏预览 | 复用真实人物详情、服饰和称谓 | 绑定已编译快照，标明是否包含未应用提案 |

肖像保持现有平面线描淡彩，列表方形、半身像 2:3。编辑面板只使用适度大小的预览，不让大图挤走字段。外观配置保留遗传能力与资产引用，不把生成的人物示例图直接接入游戏。

新增流程为选择模板→填写共享档案→选择是否加入当前剧本→配置状态→校验。职位、家族、地点通过搜索选择已有实体；任职候选展示能力、资格和冲突，不仅给一个任意文本框。编辑开局任职可配置，但仍受唯一性、存活、所属制度及兼任约束。

批量导入先生成差异，报告重复 ID、缺失引用、亲缘循环、日期和任职冲突。导入失败可修正重试；不得自动把未知人物当成新人物或把同名人物合并。

### 6.3 剧本编辑器

剧本负责组装完整开局，是创作台默认入口。新建从复制已有剧本或选择基础包开始。复制后显示待复核事项，不把改年份当成历史剧本已经完成。

同级工作区包括：基本信息、初始世界、人物政权、经济军务、事件规则、开局引导。首屏常显剧本名称、日期、历史／架空标记、依赖版本、完整性清单和地图预览；点击问题直达对应编辑器并保留返回路径。

- 基本信息：稳定 ID、名称、描述、封面、起始年月日、作者、资料范围。
- 初始世界：地图包、启用地点、行政版本、法理归属和实际控制；地理底图与该剧本覆盖分别呈现。
- 人物政权：启用人物、可玩候选、君主和实际执政者、首都、官职、外交、家族及初始关系。
- 经济军务：人口、公私钱粮、设施、驻军、统帅、兵额来源、装备与补给；资源预估复用初始化结算。
- 事件规则：事件包、既有制度／政策组合、阶段初态、已发生事项；不开放任意代码。
- 开局引导：推荐人物、真实身份和局势说明，不杜撰派系特性或外交关系。

初始化顺序：解析包与日期→确定实体与行政版本→校验角色关系→加载开局资源→按来源配置军队与其他占用→计算剩余资源和派生状态→运行完整开局一致性检查→创建实例。阶段顺序须在实施中明确依赖，禁止先结算默认 546 世界再覆盖年份。

资源采用“配置前总额→开局配置占用→开局可用余额”的口径，展示每笔兵员、军粮、装备成本的来源和去向。人口包含口径、军人是否已计入总人口须在 Schema 明确，不能由 UI 猜测。作者可设置初始总额，但生成世界不能重复计入军队及县域人口。

修改日期后重算年龄和适用关系，生成待复核清单；任职、驻地、外交和历史资料由作者确认，不让 AI 自动推断为史实。缺失数据可以保存为草稿，开局必要对象缺失时阻止试玩。

### 6.4 地图编辑器

两种显式模式：“地理底图”编辑共享地点、道路和地理资产；“剧本局势”编辑当前日期的行政、归属、控制、官员和资源。切换模式时显示作用域，不因地图选中而修改共享数据。

地点坐标与展示投影保持真实映射；地理邻接、行政父子、道路通达分别建模。领土边界有来源及有效日期，生成示意不冒充历史疆界。重新生成派生边界先预览差异，不覆盖人工边界；缺资料显示覆盖范围。

移动地点或修改道路时同时预检行程成本、寻路缓存和引用。旧运行实例继续使用原内容版本；已开始旅程的旧路线由绑定版本或明确迁移处理，不悄悄换成新道路。首期支持节点、连线、已有区划归属和派生结果预览，手绘多边形与复杂 GIS 导入后置。

### 6.5 事件编辑器

优先结构化表单、条件积木和分支列表，再按需求提供同一数据的流程图；不建立平行可视化脚本语言。字段包含对象绑定、触发时机、条件、概率与冷却、阶段、选项、真实行动、可见性、决策权限、NPC 倾向、超时与异常收尾。

条件注册项提供类型化参数、查询与可读解释；行动注册项提供资格检查、预估、实际执行和结果。禁止任意 JavaScript 或自由表达式执行。涉及概率时使用实例随机源，记录种子和执行顺序；接受度不冒充成功率。

绑定分为指定人物及角色选择器，明确触发时固定或每次解析。作出选择时重新检查权限和目标；NPC 使用同样的合法性检查，不能替玩家决定。对死亡、离任、被俘、目标移除、战争结束、无合法选项、超时和取消明确收尾。

一组后果在世界副本完成全部前置与结算后提交，效果回执与世界同时保存，读档／重复命令不得再次发放资源。后果记录真实战争、条约和差事 ID，事件描述不代替实际世界状态。

调试回答“为什么未触发”“为什么不能选择”“NPC 为何选此项”“为什么未结束”，逐项显示当前值、要求与未满足原因。强制进入阶段仅用于隔离测试；局部模拟有步数、时间和循环预算，达到预算返回未完成，不当成通过。

侯景事件先作为专用处理器注册并接入诊断，不一次性重写。先用一类短政务事件和一条短分支链证明配置能力，再分段迁移；每个阶段保留兼容测试。

### 6.6 政权、资产与资料辅助面板

政权区分稳定 ID、国号、家族、君主、执政者、制度模板和视觉风格；新朝国号等沿用现有项目规则。只允许组合已支持机制，不能凭空创建未实现的制度效果。

资产支持按类型、用途、来源和许可筛选，显示缺失引用。必要运行资产缺失阻止可运行导出；有明确定义降级外观的非关键资产可警告并使用占位。资料按实体挂接原出处与作者注释，未知许可不得标为已授权。

## 7. 校验、试玩与存档

| 层次 | 检查内容 | 处理 |
| --- | --- | --- |
| 结构 | 类型、单位范围、重复 ID、资源路径、依赖和引用 | 不合法的运行包阻止编译；草稿可保存 |
| 世界一致性 | 日期与存活、任职和首都、亲缘环、行政控制、资源来源 | 错误定位字段；资料不确定性单列警告 |
| 行为 | 触发和收尾、NPC 选择、资源守恒、取消、重复命令与读档 | 针对当前变更运行局部场景，报告实际覆盖 |

校验报告绑定草稿修订、内容摘要、检查器版本及范围。修改后标记相关结果过期，不能沿用绿色状态。通过静态检查不等于已经试玩；例图里的通过状态不是本项目实际测试结果。

试玩有“从剧本开局”和“局部测试场景”两种入口，实例拥有独立存储命名空间。默认内存状态，可显式导出测试存档以验证往返；不得访问线上存档接口或覆盖正式 IndexedDB。需要异常注入的测试标明测试初态，不冒充合法开局。

复现信息至少包括内容锁、规则与模拟器版本、种子、初始场景、命令序列、推进预算、失败步骤和断言结果。不默认执行模拟年／长局测试，长局及完整游戏回归只有用户明确要求后才能运行。

存档头保存格式版本、规则兼容版本、剧本 ID、精确包版本及摘要。加载顺序为读头→解析对应内容集→建立实例注册表→执行明示迁移→校验世界→恢复。缺包或摘要不符明确阻止，不回退官方 546。官方旧档通过专属适配器识别；迁移保留原档，新内容包不能被旧迁移补入官方人物和朝廷。

## 8. 文件、导出与安全边界

首期本地优先。工作台 UI 与 CLI 使用同一个本地工作区服务，限定已选择项目目录和本机接口；本地来源校验、会话授权和操作范围校验在服务端执行。浏览器不能任意访问磁盘；ZIP 作为可移植交换方式。具体运行包装在第一阶段验证，但不改变统一服务和权限合同。

导入处理路径穿越、符号链接越界、重复路径、大小与解压预算、资源类型和摘要；数据包不携带可执行脚本。资源预览不能因文档或 SVG 内容执行任意代码。运行依赖和敏感配置不混入导出包。

保存草稿、备份项目、导出可运行包、发布到游戏是四种动作。首期只提供前三项；发布继续遵守项目独立授权与原有发布流程，不在编辑器中默认接上线上部署。

## 10. 主要风险与设计决策

| 风险 | 已选路径 | 需要在实施时证明 |
| --- | --- | --- |
| 静态数据依赖远多于表面入口 | 按功能切片注入注册表，兼容旧调用 | 两个实例互不串数据和缓存 |
| Schema 足够通用但事件无法表达 | 先有限能力注册＋两类真实内容 | 不靠任意脚本绕开注册能力 |
| 人机同时写入导致覆盖 | 修订锁、前置值、原子变更、幂等回执 | 冲突、崩溃恢复、撤销依赖均可解释 |
| 复制剧本被当成新史实 | 保留来源与待复核清单 | 日期变更后不静默沿用错误任职 |
| 试玩污染正式存档 | 分离存储适配器与内容绑定 | 正式存储及网络保存端点零写入 |
| 制作界面超出实际规则 | Schema 与注册能力驱动可选项 | 不展示没有消费者的“效果” |

待第一阶段技术验证的细节：现有静态读取的完整迁移范围、本地工作区服务的运行包装、官方旧档的可用代表样本、首批可注册行动。缺少样本或实现能力时记录阻塞或缩小公开能力清单，不以伪造测试、演示数据或降低规则替代。

执行顺序、阶段门槛与授权边界见[实施计划](内容创作台实施计划.md)。本方案不承诺工期；工作量评估应在静态依赖清单和第一个纵向切片完成后更新。

## 11. 阶段 1 实现边界（2026-10-14）

完整实现和验证入口见[实施计划第 10 节](内容创作台实施计划.md#10-当前实现入口与验证2026-10-14)。本阶段已经将官方可序列化内容编译成完整包，正式 Worker 在导入规则前校验并绑定；每个不同内容实例拥有自己的 Worker／SSR 模块图，模块内缓存不会跨包共享。原只读目录仍用于查询，其摘要不代替完整包锁。

这是依赖既有 `three-realms-v1` 引擎和同版资产库的编译包，允许在该配置下修改数据并隔离试玩，不接受任意代码，也不将更改日期当作完成另一个时代的史料和机制配置。规则、资产和包版本不匹配时明确拒绝。新存档包含内容锁，官方旧档只进入官方兼容路径；原始旧档文件不被工具覆盖。

首期隔离采用完整模块环境，不在共享进程中反复切换全局“当前包”，也不要求一次性给所有规则函数增加注册表参数。正式游戏 UI 仍读取官方数据；自定义包只进入隔离试玩，后续人物／剧本 UI 通过统一宿主和编辑服务接入。

下一阶段是草稿事务、版本冲突、差异审阅与人物／剧本编辑器。独立资产打包交换、通用事件编排及第二剧本完整验收继续遵循原阶段划分；本轮没有提前认定这些能力完成。

## 12. 阶段 2 实现边界（2026-10-14）

本节更新第 11 节的阶段性状态。共用服务、CLI 和人物／剧本 UI 已接通，实际入口、字段与事务合同、人工验收顺序和验证结果见[实施计划第 11 节](内容创作台实施计划.md#11-阶段-2-实现与使用2026-10-14)。正式游戏和作者工作区分离，数据进入独立实例后实际开局；AI 默认只能提案，人工审阅或精确授权后方可应用。

首期“共享定义”限定本工作区，不写官方共享库。人物编辑覆盖基础档案、家族／亲缘和剧本初态；任职只配置现有规则支持的县级主官，不以称谓代替实际中央权力。剧本复用当前三政权、地理与事件内容；日期变化不自动完成另一个历史时期的史料配置。备份可包含无效草稿，可运行包导出须通过结构、引用与实际开局检查。事件、地图、跨规则版本迁移和备份导入界面仍按后续阶段推进；UI 仅实现，尚未人工验收。

# 侯景之乱触发链诊断

类型：机制说明（原始诊断与修复记录）。
范围：侯景之乱（`hou-jing`）历史事件从 dormant 阶段出发的触发条件，及默认沙盒中触发链沉默失效的原因。
状态：2026-10-19 异地主官裁定死锁、独立内战强攻／招降限制已修复；通用战后秩序与地方另立 C＋D 已本地实施。第二轮规则／Worker 流程复测发现两项推进缺口、一项改编提示缺口，尚未修复，详见文末。正常玩家起兵和战败可收场；隔离胜利档须先释放被俘萧衍才可交权，不能据此判为整体通过。界面、自然胜利和完整战后待遇实机履约仍未验收。原始诊断与历次修复记录保留，不据单局结果统计自然起兵概率。
核对依据：`src/core/historicalEvents.ts`、`src/core/world.ts`、`src/core/realm.ts`、`src/core/armyOrganization.ts`、`src/data/campaignSetup.ts` 实际代码；2026-10-17 用固定种子确定性模拟（`newCampaignWorld('yuwen-tai', …, 'sandbox')`，零玩家干预）复现并逐日记录触发链输入项。

## 原始诊断结论（修复前）

不是随机 bug，而是**触发链第一道门槛被常规战况永久打断**：事件触发器要求侯景在"保护人去世/病重"发生时仍握有 ≥100 人的军队，但默认沙盒的确定性战况会让侯景在高欢去世前两年就失去全部军队，且此后无人再授兵给他，事件因此永远停在 dormant 阶段，侯景之乱不会发生。

## 触发链结构与唯一出口（修复前）

事件实例由 `ensureHistorical` 创建（`historicalEvents.ts:23-26`），初始 `phase:'dormant'`、`actors.protector:'gao-huan'`。每日世界推进末尾调用 `advanceRegisteredEvents`（`world.ts:282`，在 `advanceLife` 死亡结算之后，时序无问题），进入 `advanceHistorical`（`historicalEvents.ts:147`）。

dormant 阶段的唯一出口是 `northConflict`（`historicalEvents.ts:196-199`），其首道门槛（`historicalEvents.ts:39`）：

```ts
const r = allegianceRealm(w, person), army = historicalArmy(w, person);
if (!r || r !== e.origin || !army) return '';   // 无兵直接返回，后续条件不再评估
```

`historicalArmy`（`historicalEvents.ts:28`）要求存在 `troops>=100` 且由侯景拥有或指挥的军队。即使走"病榻议事"路径（高欢重症 severity 3，`historicalEvents.ts:46-48`），同样先经过这道门槛。

## 高欢去世时刻的条件核验（模拟实测）

当前构建（含 2026-10-17 高欢「军务积劳」健康修正）默认沙盒中，高欢卒于 day 851（548-05-01）。当天各输入项：

| 条件 | 要求 | 实测 | 判定 |
| --- | --- | --- | --- |
| 侯景在世 | `isAlive` | 在世 | ✅ |
| 侯景统属东魏（=事件 origin） | `allegianceRealm===e.origin` | east | ✅ |
| 保护人去世/失势/重病 | `!isAlive(protector)` 等 | 高欢已死 | ✅ |
| 侯景厌恶现任执政 | `relationOpinion<=-30` | 对高澄 −30（初始值恰好 −30，临界满足） | ✅ |
| 90 日内无 kept 担保 | `assurances` | 无 | ✅ |
| **侯景握有 ≥100 兵力** | `historicalArmy` | **无任何军队** | ❌ |

→ `northConflict` 返回空串，事件保持 dormant；直至 day 1032（模拟截止）仍无变化，`milestones` 为空。

## 次级排查项（若具体存档与默认局不同）

以上复现针对默认无干预沙盒。用户具体存档若在高欢去世时侯景**有兵**而未触发，才需要依次核验：

1. 侯景对东魏执政者好感被互动抬升超过 −30（`relationOpinion`，`relationships.ts:51-76`，基础值不随时间衰减，但会被 `changeRelationOpinion` 修改）。
2. 90 日内存在 `status:'kept'` 的担保（`historicalEvents.ts:45`）。
3. 侯景统属已变化（`allegianceRealm` ≠ east）。
4. `campaignSetup.politics.nativeEvents` 未包含 `'hou-jing'`（则事件列表为空，`historicalEvents.ts:25`；官方默认 `politics:null`，不触发此问题）。
5. 存档早于事件功能、且加载迁移后仍未生成（`parseWorld` 会补 `ensureHistorical`，`save.ts:211`，正常情况下旧档也会补建）。

核验需要该存档的导出文件（行记 → 导出备份）。

## 原始机制缺口小结（修复前）

- 触发依赖战况无法保证的前提（侯景常备重兵），存在设计上的沉默失效路径。
- 好感临界值 −30（初始值恰好等于门槛 `<=-30`）无缓冲，一旦被任何正向互动改变即失效，属于次级风险点。
- 修复方向（未实施，待决策）：如"无兵亦可在保护人去世时触发交接交涉（以身份/影响力而非兵力为前提）"、或"东魏在保护人交替时主动重授侯景兵权"等，需与既有规则（撤将拒令、部曲改编）一并设计。

## 2026-10-17 已实施修复

- `northConflict` 不再把现存百人军队作为政治交涉的前置条件。侯景仍须统属事件原国；保护人失势／死亡／病重、实际执政者／继任者关系、失信／追索与近期待遇担保等仍按原规则判断。撤将／解散拒令只从真实存在的军队读取，不补造已灭军队的拒令。
- 无兵也会进入 `north` 交接阶段。原国玩家实际执政者获得待遇裁定，玩家侯景可选择个人归附；无兵时携军方案继续禁用并解释原因。NPC 先尝试所有可达政权的合法携军归附，再尝试个人归附，仍需真实道路、影响力 20、身份、行程与在办事务条件。全部请求暂时不可行时保留原待决，后续稳定边界重新检查，不把一次受阻永久记成放弃。
- 个人归附沿用原约定系统：双方接纳前不转属，生效只改个人效忠，不赠兵、不花武装保护预算、不转移县域；此分支以个人安置结案。携军归附、保护争议与公开起兵继续复用原规则；实际起兵仍需支持地区的真实地方军至少 300 人，以及实际基地、公款、公粮、私财与影响力，未保证高欢一死就强制爆发战争。
- 旧档中仍为 dormant 的事件，从下一次事件检查直接按当前事实进入交涉，无须重开，不复活、重置战损或补发军队。事件与存档数据结构未新增字段，精确登记修复前官方锁以供生产构建恢复旧档。
- 新增七项局部回归，先复现修复前六项失败，再验证无兵旧档、NPC／玩家路由、个人归附成本与兵财不变、实际执政者担保、好感及担保门槛、受阻后重试、原有携军优先和真实起兵兵力门槛。本轮不重复原诊断中的千日模拟；其他相关检查见实施记录。

## 2026-10-17 修复后复测（第二轮只读诊断，未改代码）

用户反馈修复后仍未见侯景之乱。用同一确定性模拟（宇文泰玩家、零干预）重跑全程，结果：**触发端已修复，事件如期发动，但接纳端把事件静默结案，战争仍不可达**。

### 阻断点一（本次根因）：NPC 接纳好感门槛高于默认异国好感

- NPC 政权自动应答 pending 归附的唯一逻辑：`allegiancePacts.ts:97`——`if(relationOpinion(w,chief,p.person)>=-10 && !pactReason(...)) perform(accept)`。
- 萧衍对侯景的初始好感为异国基础值 **−25**（`relationships.ts:54`，两国不同政权且无历史好感条目）；按 `campaignSetup.ts:30`，初始好感条目只有侯景→高欢 +30、侯景→高澄 −30，**萧衍→侯景无任何加成**。
- −25 < −10 → NPC 萧衍**确定性地永不接纳**侯景（个人或携军都一样），请求只能在 30 天后逾期。
- 逾期后事件按 `historicalEvents.ts:197` 结案，且**不会改投西魏重试**（重试逻辑 d159997 只覆盖"请求被条件阻止"的情形，不覆盖"请求已发出但被冷落"）。

### 阻断点二（次级）：即使被接纳，无兵也只能和平结案

- 无兵时携军条款（retain）被 `pactReason` 拒绝（'须本人随实际统领或所有的部队驻留'，`allegiancePacts.ts` request 分支），唯一可行条款是 `personal`。
- 个人归附生效后事件立即按 `historicalEvents.ts:186` 以「个人归附已完成，未接收独立军队」结案——**仍无侯景之乱战争**。
- 战争路径（dispute→crisis→rise→rebellion）要求携军条款 + 真实兵力：实际起兵仍需支持地区真实地方军 ≥300 人及基地、钱粮、影响力（见已实施修复记录末条）。

### 结论

默认零干预世界中，修复后的事件链路是"触发 → 来书 → 无人接纳 → 逾期结案"，侯景之乱战争**在没有任何玩家 orchestration 时不可达**。两条出路都依赖玩家介入：

1. 玩家扮演萧衍（或梁执政）并手动接纳——但按阻断点二，个人归附仍和平结案，要走向战争还须侯景有真实军队（如玩家在东魏执政时于高欢死前重新授兵给侯景）。
2. 调整 NPC 接纳决策（如历史事件背景下的定向豁免/权重，或好感门槛对归附请求单独放宽），并考虑逾期后允许改投他国重试。

## 2026-10-17 用户提案评估（只读评估，未改代码）

用户提案：① 去掉 NPC 接纳的好感度要求（`allegiancePacts.ts:97` 的 `relationOpinion>=-10`）；② 侯景决定归附时额外授予 800 部曲（复用现有「私募部曲」入口）。评估结论：**两条都对症，但都做满也只走到"驻梁"，到不了"起兵"——还缺第三环**。

### 提案①评估：方向对，但"全去掉"影响面大于必要

- 该门槛是**全局归附系统**的 NPC 自动应答条件，不只作用于侯景；去掉后任何 NPC 政权对任何来投者（含携军叛将）都会无条件自动接纳，只剩道路/保护预算 100 钱/外战<6 等机械校验。
- 注意 `pactQuote` 已产出 `acceptance = 侯景对执政好感 + 20（携军）` 字段（目前仅供 UI 展示，无任何消费者）——可以把它接入 NPC 应答代替裸好感判断，而不是简单删除。
- 建议：携军条款放宽或改用语义化的 acceptance（携军 +20 后侯景 −25+20=−5，可通过）；个人归附可维持较严。这样既不破坏全局系统，又能让本事件通行。

### 提案②评估：机制契合度很高，但必须带"来源与成本"三要素

契合点：

- `privateRaise`（`militaryCareer.ts:32-63`）产出的私军参数（`owner=本人、loyalTo=本人、commanderLoyalty 60、institution 30`）恰好满足 `pactQuote` 的"追随"判定（忠诚度 ≥60 且 > 制度值 → 800 人全部计入携军兵力），retain 条款的 ≥100 人门槛直接通过。
- 800 规模合理：开局各国军队 600 人/军，800 私军足以独立编制但不碾压；私募默认上限即 200/次、目标军 6000 上限内。

必须补的守恒要素（项目约定第 4 节"征募落实来源、不无偿造人"）：

| 要素 | 现有机制可复用 | 若缺失的风险 |
| --- | --- | --- |
| 人口来源 | `recruitmentSources`+`consumeManpower` 从驻地县域兵额扣除（"来源兵额保留"可溯源） | 凭空 800 人违反守恒，数值审计不过 |
| 钱粮成本 | `privateRecruitmentQuote`：兵装费（兵种价×人数/200）+ 军粮 0.3/人（庄园粮+公库购粮） | 同上 |
| 付款主体 | 侯景私财（若不足则以"剧情专款"名义标注来源，如河南旧部自筹） | 无来源标注违背"预算须可追溯" |
| 归属与训练 | `trainingStarted/readyDay +30`、"满百人才可独立出征" | 新建军团即战会绕过训练规则 |
| NPC 兼容 | `privateRaise` 现硬编码 `w.characterId`/`playerRealm`，NPC 不可用——事件授予需走 actor 参数化或独立授予函数复用同一套来源/成本/编制逻辑 | 直接调玩家入口会对玩家再收一次费/错挂国家 |

时点建议：在事件进入 `north` 阶段（高欢死亡当日）授予并对侯景"决定归附"的决策可见，叙事上即"河南旧部闻讯来投"，与史实（侯景携河南兵南奔）对齐；授予后 NPC 先携军条款求附（现有顺序已如此），无需改决策顺序。

### 缺失的第三环：crisis→rise 的 NPC 好感门槛（−40）

- 即使①②全部完成：侯景携 800 人驻梁、归附生效 → 事件进入 settlement。**争议的自然来源很弱**：`currentPactBreaches` 只有"被拘/约定兵权被撤/连续欠饷"三条，没有 NPC 逻辑会主动撤侯景的兵权；安全交涉链（`syncSecurity`）需要东魏与梁先出现停战/和约信号才会启动"追索降将"剧情。
- 即便争议成立进入 crisis，`npcDecision` 的起兵分支要求 `relationOpinion(侯景→接纳国执政) < -40`（`advancePacts` 的自动起兵同样是 −40），而侯景→萧衍默认异国基础好感 −25 → **NPC 侯景确定性不起兵**，事件仍和平结案。
- 可选补齐方式（任选其一，未实施）：a) 事件感知——历史事件持有的 crisis 决策对 NPC 侯景免除/下调好感门槛（事件本身就是"惧祸起兵"的剧情授权）；b) 初始数据——为侯景→萧衍增设负向好感条目（如 −45），让默认世界线自然走向叛乱；c) 接受"玩家扮演侯景时手动起兵"作为战争的唯一触发方式。

### 综合判定

| 提案 | 判定 | 建议 |
| --- | --- | --- |
| ① 去掉接纳好感要求 | 部分采纳：问题定位准确，但"全去掉"过宽 | 携军条款改用 `acceptance`（自带 +20）或门槛放宽至 −40；个人归附维持原门槛或单独校准 |
| ② 授予 800 部曲 | 采纳（带条件）：机制契合度高，是走到"驻梁"的必要条件 | 必须复用私募部曲的人口扣除/钱粮成本/30 日训练；付款主体标注来源；NPC 走参数化授予路径 |
| （新增）③ 起义门槛 | 必须补齐，否则①②做完仍无侯景之乱战争 | 事件感知免除 NPC 好感门槛，或补侯景→萧衍初始负好感条目 |

## 2026-10-17 第三轮：转化率改造（已实施）

按用户确认的方案落地，目标不是强制必反，而是让“有兵、有怨、有真实接纳空间”的局能走完。以下数值均为游戏参数，不是史实断言。

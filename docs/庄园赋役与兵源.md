# 庄园赋役与兵源实施

依据「评估庄园机制」最后一版简化方案（2026-10-09）。本轮已获验证与实施授权；不推送或部署，UI 由用户人工验收。

## 范围与验收

- A：稳定 ID 的公私共用庄园实体；在庄人口为县域民用人口子集；人口承载、三档租额、自动经营、公私产出一次分配。
- B：现役及返乡在途占用同源兵额；中央、地方、差事、批量与 AI 共用校验；私军改编保留来源类别；赋役在地方成功执行后生效。
- C：复用庄园画面，补经营确认与实际预测；县域、家族和征募显示权威数据；NPC 低频经营、产权继承和失守停提。
- 局部验证守住人口、公私钱粮、兵源、幂等、原子失败及旧档迁移；保留构建检查。长局与全量回归不在本轮授权内。

## 数值定义

| 字段 | 类型、持有者、单位、范围 | 来源与消费者 |
|---|---|---|
| 庄园 `population` | 存量，庄园，人，0—县域人口 | 同县招佃/离庄、征募/返乡、损失；生产、租额、动员 |
| 庄园 `grain` | 存量，庄园，粮，0—庄仓容量 | 从县域一次产出分配，经营损耗；招佃、赈济、本地部曲 |
| `owner/id/location/family` | 产权与定位元数据 | 置业、继承、处置；权限、收益收款与来源追溯 |
| `rent` | 三档状态，庄园 | 玩家或 NPC 决策；分租和月度流动 |
| `rentChanged/lastDecision/lastMonthly` | 日期元数据，世界日 | 季度冷却、NPC 低频决策及月结去重，不生资源 |
| 县域 `estatePolicy` | 三档实际状态 | 成功完成核籍差事；农业税与公私动员份额 |
| 兵团/返乡 `sourceEstate/quota` | 来源元数据 | 征募时固定；改编不重置，死亡/安置释放额度 |
| 承载、普通编户、可征兵额、月收益 | 派生值 | 建筑、权威人口、实际政策与同源现役/预留；不保存第二份余额 |

## 实施记录

已实施 A、B、C。旧版主庄园保留为兼容的首个权威实体，新增庄园登记在同一 holdings；统一查询包含两者，登记表不重复保存主庄园。

- 新沙盒局给主要产业人物划出 1200 人以内的庄户，来自所在县民用人口；规模、田庄承载与 4% 动员比例都是游戏配置，非精确历史庄产。现有剧本开局无现役军队，4% 不造成开局超额。教学局保留原简化收益，完整人口/赋役经营只用于沙盒。
- 田庄每级承载 2000 人，庄仓基础 100 粮、每级增加 400。置业支付民间费用 80、田庄施工 40，十日竣工；建设中的田产提前占县域经营容量，不赠人口。招佃每十人 1 钱、每百人 1 庄粮；同源未落户兵员继续占安置规模。
- 三档租入份额为 25%/40%/55%，90 日调整冷却。正常常额在安定有粮时不自动流动；月度县内依附变化上限为民用人口的 1%，竞争和流失均按统一比例分配，舍弃不足一人的余数，不按遍历顺序抢人口。
- 税赋与兵额分别用 40%/70%/100%、公军 25%/50%/75%，只在合格地方清税/核籍差事结案后切换。一次追征回款保留原流程，长期农业税变化独立预览，不重复发放。关系反馈同一受影响庄主仅一次；集团仍用既有地方公务反馈。
- 现金租入来自农业现金产出与有真实庄户劳力的加工；粮租来自县域扣基本民食后的剩余产出，未再次折钱。县域收成只算一次，庄粮分走后其余进入公粮结算，民食只扣一次。仓储损失及溢出在月结纪事中记录。庄主钱包满时未能提取的钱不计入私人余额。
- 所有征募、地方动员、军务差事、批量计划、军务 AI 和民变征募接同源公共额度；私募有庄产时接本人私人额度，无庄产须有军务授权并占公额。操练只训练现役，补兵另付钱粮、训练。新私募允许小批次，优先填入兼容部曲；百人以下保留编制但不能独立出征。
- 来源随兵团、退伍在途及伤兵/战俘/散兵留存，改编不刷新额度；死亡释放兵额，幸存者落户才进民用人口。异地安置沿用旧规则、转普通编户。旧私军不能确定庄源时用兼容私人类别占普通来源总额；旧伤亡池无法追溯祖籍，明确以原池地点作兼容来源，不猜造庄园。
- 产权接入家业交接与死亡：有效继任者承继原地资产，无继任人回普通经营、庄户转编户、库存及未完工程处置可查；失守保留实体和粮食，原主暂停提租、取粮与征募。NPC 每季最多一项调租/扩建/招佃，使用本人钱包。
- 庄园、私财、县域、中央公库、家族、单次和批量征募及核籍预览已补权威信息；画中营建保留，新增经营选项在确认弹窗中调整。交互参照 [CK3 官方 UI 说明](https://www.paradoxinteractive.com/games/crusader-kings-iii/news/ck3-console-dev-diary-3-uiux-and-controls)，视觉沿用墨绿、旧金、纸色与画中建筑，题材参照 [《全面战争：三国》官方介绍](https://asia.sega.com/totalwar-three-kingdoms/en/)。无新增外部美术资产。

## 验证记录（2026-10-09）

- 庄园专项 20 项通过，含人口/库存守恒、公私额度、竞争顺序、NPC 私财与季度幂等、失守、继承/处置、预留、旧档迁移（含已继承家业）和月结去重。
- 直接相关 construction、armyOrganization、policyExecution、monthlySettlement、lifecycleIntegration 局部测试通过；军事集成所选 9 项、差事所选 14 项、操练用例通过。军务返乡、吞并和政策的相关用例已验证。未重复运行不受改动影响的通过项。
- `npm run build` 与 `git diff --check` 通过。构建仍有原有大 chunk 提示。
- 整国割让的旧军事集成用例仍失败：旧预期允许普通割地交割对方全部县域，现行规则要求明确吞并；在改动前的本地基线副本中也失败。本轮未改该用例或战争范围规则。
- 差事文件中自带 370 日长局被误选，发现后中止，后续验证明确排除；不作为本轮完成证据。没有完成长局平衡或全量回归。
- 本地 `http://127.0.0.1:5173/` HTTP 200；未以浏览器、截图或自动化做 UI 验收。人工待验：庄园经营弹窗、多个庄产/外国庄主查阅、钱粮/兵源预览、页面滚动与焦点返回。

## 庄园详情重做与浏览器验收（2026-10-10）

用户批准按预览落地，并明确授权本轮浏览器美术与交互验收。采用独立墨刷窗口，左侧固定庄主、地点与六项资源，右侧单层「营建／经营／庄粮／家事」页签；复用现有山水、建筑及真实人物肖像。预览示例数值未写入游戏。建筑按真实等级、未建、施工、竣工状态展示，待完成效果明确标为「竣工后」。

- 营建在画中建筑附近预览并确认；招佃、调租、置业、赈粮和提粮进入对应弹窗。家事明确参与人物、地点和费用；选择只改草稿，提交复核原规则。页面或庄园切换清理草稿；Escape 优先关闭子弹窗，取消及提交回执后恢复操作入口焦点。
- 浏览器发现并修正了共享样式覆盖（标题压页签、纸色建筑标签、墨刷背景失效、纸面浅字），以及资源不足时预估保持原值、提交期间入口禁用导致焦点丢失。顶部 OngoingFlags 与 ArmyDock 原来共用同一个 React key，已分别加稳定前缀，生命周期仍按原 game.entry 重置。
- 1920×1080、1366×768 实机检查四页签、选中态、摘要及操作区；最终摘要/工作区 scrollHeight 与 clientHeight 相等。复核庄园→县城→返回、庄园→人物→返回，以及本人庄园切换的对象和操作目标。

# 人物形象与遗传系统

2026-09-22。分层立绘、形象存档及遗传计算已实现；婚育与新生人物进入世界尚未实现。以下规则是游戏设计，非真实人类遗传模型或历史人物容貌考据。

## 数据与表现分离

| 层次 | 当前内容 | 变化来源 | 是否遗传 |
| --- | --- | --- | --- |
| 遗传参数 | 面容类型、脸宽、色调，体健／敏锐各两份等位参数 | 初始配置；未来出生时双亲取样 | 是 |
| 形象身份 | 男／女性别表现，江南／北地衣冠分组 | 人物配置；未来文化转变 | 不由本次遗传算法复制 |
| 职位衣装 | 常服、治事官服、军旅甲胄、君主礼服标识 | 历史初始身份、实际任命、军务动员、退居 | 否 |
| 性格表现 | 六种现有特质纹章；书卷、钱囊、绳结 | 当前人物特质 | 不直接遗传 |
| 状态表现 | 高压力的暗色画缘、多疑的冷色画缘 | 当前压力与特质 | 否 |
| 后续人生经历 | 伤疤、衰老、疾病、成长体态 | 未来事件与年龄系统 | 不进入胚系参数 |

文化是衣冠与生活传统，不是民族血统或能力等级。当前按剧本政权给出两种初始衣冠方向，只是美术分组；切换文化不会改变脸型、肤色或先天能力。性别也不决定能力、性格或服装职位可用性。现有历史人物性别配置为男性，女性素材支持预览及后续人物接入，不擅自新增历史女性或亲属。

## 原组合方式（已由下述五官系统替代）

`CharacterIdentity` 保存性别、衣冠文化与版本化 Genome；`portraitContext` 从世界读取当前身份、特质、压力及职务，`composePortrait` 生成图层选择和形态参数。`LayeredPortrait` 为通用渲染器，接受名称和上下文，不要求人物必须在历史名录中。

绘制顺序为纸底 → 面容 → 衣袍／甲胄 → 职位印绶或佩玉 → 特质随身物件 → 特质纹章。两张面容图集各四种基础脸型，一张衣装图集包含南北两组文服和甲胄。脸宽及色调从参数表达，头部和衣装独立替换。职位优先级：退居常服；当前人物取得军务授权且本国存在动员军队时穿甲胄；其余使用初始身份或实际治理权限。

现阶段五官、发型、胡须仍绘制在同一面容模块中，尚未分别拆成鼻、眼、口、发束；没有年龄分段与完整换装库。特质影响物件与纹章，压力影响画缘，不声称已有面部表情动画。勤勉、慷慨、坚毅分别选书卷、钱囊、绳结，多个特质时按此顺序选一个物件；所有现有特质纹章均保留。后续拆五官需要美术锚点和遮罩配套，不能仅增加字段。

所有人物入口默认组合立绘，同时保留原版单人定稿切换。展开“形象构成与试装”可预览性别、文化、职位、面容和性格搭配。预览明确标注，不写世界、不改变人物身份、资源或实际特质；恢复或重新打开即可回到当前人物。每个图层独立处理载入错误和重试。浏览器外观与拼接效果须人工验收。

## 遗传计算契约

`inheritGenome(parentA, parentB, seed)` 仅接受版本 1 的合法参数，返回 `{genome, nextSeed}`。每个位点由 A 的两份中等概率抽一份、B 的两份中等概率抽一份。输入不变；相同双亲及种子得到相同子代；接续 nextSeed 可产生不同手足，且重载不会重新抽取。当前没有突变、连锁或近亲惩罚。

面容类型在四个美术档位之间取双份平均并取整，脸宽和色调取平均。体健、敏锐暂使用游戏化的隐性表达规则：两份均为 1 才表达；单份为 1 的携带者可以继续传递。它们目前只保存在先天参数及说明中，不影响现有能力或经济数值；不能与六种现有性格特质混为一谈。

初始历史人物参数由稳定 ID 确定性生成，仅作美术参数，不推断真实血统或生母。现有父子／兄弟的史料关系保持原状，不倒推或伪造缺失母亲；也不声称首批人物已形成遗传一致的家谱。

世界增加可选 `identities` 版本 1；新局写入首批 12 人，旧档读取时确定性补齐。存档校验检查成员、性别、文化、位点和值域，损坏数据拒绝载入。已有字段不重新生成，后续美术更新不能使同一存档的人脸随机变化。

## 后续出生与成长接入顺序

1. 扩展人物实例名录：世界内唯一 ID、姓名、出生日期、父母 ID、性别、文化、家族与 Genome；历史名录作为初始模板。同步替换社交、继承和存档中固定 11 人／4 个行旅人物的假设。当前校验仍限制已录人物，不能直接把遗传结果塞入存档充当可玩新人物。
2. 婚育事件由 Worker 验证双亲实例、年龄和事件权限，使用世界专属出生 RNG。一次事务同时写子代身份、亲属关系、Genome、生日与 nextSeed，再持久保存。事件需唯一 ID 防重复；保存失败须沿用现有回滚规则。不能在 React 渲染时抽取遗传结果。
3. 文化和家族由养育规则选择，不从脸型或基因推断。幼年、少年、成年按年龄加载对应素材，未成年不能借用成人头像冒充完成。
4. 性格由成长事件、监护人示范和玩家选择获得。父母性格可提高养育事件的权重，不强制复制；同类冲突性格要校验。学习、教育特质和官职不作遗传。
5. 先天特质如需进入能力系统，先设计影响幅度与互斥规则，再加入 `attributes`、规则与存档验证。目前不偷偷改变原有平衡。

## 验证与验收

自动验证覆盖双亲各取一份、携带与表达、随机状态继续、输入不变、非法基因拒绝、存档往返与旧档补齐、文化／性别／职位不改基因，以及任命／动员／退居选择衣装。构建检查所有 TypeScript。

人工入口：人物选择页及游戏内人物详情 → 组合立绘 → 形象构成与试装。检查男女面容、南北衣冠、文武搭配、饰物与拼接比例；恢复当前人物后检查旧存档身份和原版定稿。禁止浏览器自动化验收。

素材与完整提示词：`public/art/portraits/layers/`、[人物分层素材提示词](人物分层素材提示词.md)。内置 ImageGen 原创生成；不复制商业游戏资产。


## 2026-09-23 五官组合升级

当前人物入口统一采用 `FacialPortrait` 矢量绘卷，停止使用头部／衣服图集裁切。脸长、下颌、颧骨、眼宽、眼尾、眼距、眉形、鼻长、鼻宽、口形、耳形为 11 个独立双等位位点，沿用脸宽和色调位点。颈部、耳、五官、发际和冠帽在同一 400×440 坐标系组合；眼珠裁切到眼睑轮廓，不允许各图层单独缩放漂移。面容与职位、文化分开，性别改变发式与修饰，压力改变眉态；须发和成熟度是独立美术参数，不遗传。

新局为 11 位历史人物写入各自五官配置；读取已有五位点存档时只补缺失的 `genome.facial`，保留原位点、钱粮和游戏进度；一旦存在五官位点，后续读取不覆盖。`inheritGenome` 对 11 个五官位点逐项从双亲各取一个等位值，并返回连续随机状态。本轮仍未引入出生流程和新生可玩人物。

### 验收

当前入口是开局人物选择、城市人物名单和人物详情；旧的试装面板已移除。人工比较高欢／宇文泰／萧衍／元善见的轮廓、眉眼、须发与衣装接合，检查小头像。代码测试覆盖极端参数、图层裁切 ID 隔离、历史人物配置、位点遗传与旧档补齐；不代表画面质量已经人工验收。


## 2026-09-23 立绘画风调整

针对正面镜像、头部偏大和衣袍钟形外轮廓造成的“套娃感”，改为较小头身比、轻微转头与倾角、高低肩、交叠衣袖及手部姿态。头部所有配件采用共同变换，眼球保持同方向视线；鼻口与须髭同步偏移。笔触改为细线与疏密衣纹，底色改为青灰浅纸，减弱黄褐重阴影；人物详情移除拱形肖像边框。五官基因、历史配置和遗传数据不变。

参考方向为《太吾绘卷》人物的线绘、淡设色和衣袖层次，未复制其立绘或拆取商业素材。游戏实际显示为原创参数化 SVG；画风相似程度与最终观感须人工确认，代码检查不能替代美术验收。

## C 线描淡彩：绘制部件组合试制

用户选择 C 后，独立样板入口为 `/docs/art-direction/portrait-studies/style-c/composer.html`（Vite 本地开发入口）。此页不属于正式游戏菜单；主游戏仍使用原有肖像，待新组合的人工美术验收后再替换。

- `paintedStudy.ts` 配置一种青年男性三分之四视角，八层为袍服、无五官头部、左右眉、左右眼、鼻、口。两组五官与两套袍服可独立组合；每组都来自实际绘制的 PNG，而不是 SVG 五官。
- 原图保留完整构图。运行时按登记坐标裁切五官，用局部多边形遮罩融合；头部覆盖原脸，领口使用纵向渐隐。真实素材在 `public/art/portraits/painted-c/`，并非已交付透明独立分层源文件。不得把首版不合格的 `parts-study-v1.png` 当作部件来源。
- 三项兼容条件（规格、视角、设色）必须一致。尺寸和遮罩非法时显式失败；素材失败可重试；整张合成成功后才替换画面，连续操作保留最新请求。图像缓存最多 12 张。
- 样板根据已有 `Genome.facial` 表达选择五官，形变限制在 ±6%。`inheritGenome` 分别取得双亲的一份参数；衣服不参与遗传。试换五官不改基因，重复载入相同基因不会重抽形象。预览用虚构双亲，以同一成年男性规格对照，绝非真实人物亲子关系，也不会创建游戏世界人物。
- 当前未扩展女性、年龄、脸型、肤色、须发、文化衣冠与特质配件，也未迁移历史名录。不能用单种规格声称新人物系统已完整覆盖这些维度。婚育入世界仍未实现。

人工验收：分别换眉、眼、鼻、口，观察相邻部件有无残影或色块；换袍服检查领口过渡；切换近景／半身与双亲，生成多个子代，比较组合差异。所有 UI 和合成观感由用户验收，未运行浏览器自动化。素材、提示词及溯源见 `docs/art-direction/portrait-studies/style-c/parts-v2-prompts.md`。

### 用户验收通过后的首批接入

用户已明确回复“验收通过”。上述组合样板的美术验收完成；元善见接入正式 `CharacterPortrait` 共用入口（人物选择、详情、城市人物列表）。大图显示半身，compact 显示面容近景。游戏内布局仍待人工验收，未做浏览器自动化。

`approvedPaintedRecipe` 以明确身份及规格控制发布范围，只适配北方青年、男性、无须的元善见。军旅甲胄尚无对应新素材，因此该职务使用原有造型；其他人物继续原有专属造型，避免给老年、女性或其他历史人物套用元善见底稿。君主使用紫灰袍服，治事与常服使用青袍，这一对应为美术设计。

五官仍取自现有存档，不重置 Genome、不改变世界规则；换服装不重抽脸。相同配方不随世界 tick 重绘。组件完成合成后才替换画面，卸载或切人会忽略过期请求。加载失败在游戏中显示简短提示，大图提供重试；小头像不嵌套按钮。后续仍需扩充各人物、年龄、性别、文化与职位的专属美术规格。

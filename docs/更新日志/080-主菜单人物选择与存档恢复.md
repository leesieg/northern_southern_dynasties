# 080 · 主菜单、人物选择与存档恢复

## 界面

- 主菜单使用满幅山水、墨色纵向选项和旧金选中线，继续游戏直接显示将读取的人物与游戏日期。
- 人物选择统一纸色地图、墨绿人物栏、选中边框和固定启程区；保留地图／名单／搜索联动、人物资源与亲族。地图地点支持 Enter 和空格选择。
- 主菜单与游戏内共用 `SaveBrowser`：手动、自动、切换备份分组；先选行记看摘要，再确认读取。保存覆盖、开新局、导入、读取和删除都有明确确认及忙碌状态。文件读取期间禁用重复操作。
- 复用既有场景图片和已验收的人物画风，未引入商业游戏素材；界面实际效果待人工验收。

## 存档逻辑

- 存储可用但最新数据损坏时，仍初始化恢复通道，显示原错误并允许读取其他槽位或导入；不允许用占位世界备份覆盖真实存档。
- 读档／导入前的当前世界改存到独立 `previous-run` 槽，界面统一称“切换前备份”；后续自动轮换不再覆盖它。新局同样使用此槽，既有存档槽位及账号 API 不变。
- 自动继续优先最近的手动／自动存档，只有不存在这些存档时才选择切换备份，避免备份时间较新导致跳回旧局。账号列表与本地列表都按保存时间排序。
- 切换开始即暂停。目标数据校验、备份、目标写入完成后才替换内存世界；写入失败保持原世界，刷新存档列表以展示已成功写入的备份。云端两次写入仍是顺序请求，并非服务端跨请求原子事务。
- 删除后不再把其他存档的时间冒充当前世界的最近保存时间。IndexedDB 读取补齐事务中止反馈。

# 069 · 军事系统整合

日期：2026-09-30

左侧新增军事入口，集中查看军情、军队、战争、将领、粮运与战史。右上军队栏继续常驻，详情与任将复用原入口。普通人物只可查看授权军队的精确兵力与机密军粮；地图上的其他军旗显示未知兵力或已有区域侦察估计。

## 征募、军令与人物

征募计划先整单验证各地人口、出资、粮仓、训练和集结道路，成功后统一下单；后续训练、失守、欠饷和道路阻碍仍按真实状态推进。联合军令支持统一集结、逐军分路、按粮仓分散驻防，各军保留自己的统帅、账户与忠诚。逐军可选择自主行军；亲自下令会恢复直接控制，自主模式不自动追加玩家朝廷征募或预算。

没有军权的人物可用私财研习兵法，按三十个有效驻留日完成，行旅和公务期间暂停。自荐公军由实际执政者裁定，NPC 共用现行门第/选任/考绩评价。私募从驻地真实人口与粮仓形成，主人负担军饷和军粮，朝廷接受其战役不自动取得所有权；私人安抚不能由别的操作者擅扣主人的财产。

兵团记录制度信任、原将忠诚与凝聚力。合分军保留这些状态，凝聚力影响真实战力。高度私人化的部队可能拒绝交接或遣散；安抚、清偿和改编分别有账户和条件。起兵与本人投降按兵团立场分裂，钱粮与欠饷按实际比例保留，在途粮队返回原仓。个人转国记录在权威关系状态中，解除个人誓约不会抹掉已经发生的转国，旧职权清理而城市法理不随个人变化。

## 战争、围城与补给

占领、野战和持续目标分别计分；普通累计上限 99，全部领土失控且没有至少百人的抵抗军才到 100。城市价值在开战及参战时固定，战斗结束一次计分。续战意愿独立考虑本国军力、专属其他战线的委任、预算、欠饷与粮耗。

双方可组合割地和赔款，割地可交给同阵营参战国，赔款仍归条款中的收款方；原目标赔款与附加赔款相加。盟国单独退出仅处理自身义务和占领。结束一场战争不清理另一场的占领、围城或敌对，也不强制撤走其部队。战史保存稳定身份、当时统帅、阵营与加入日期；改将或解散不倒推历史。

围城改为城市阶段判定。真实供粮兵力、城防、缺口、攻城队、城内粮、守城性格和接近援军影响下一轮迫降概率；兵力不足不能靠等时间必然拿城。封锁减少入城产出，撤围后重新计算。玩家守城主官亲自决定坚守或议降，事件待裁定时暂停，读档继续等待。

补给按库存、提前期和可靠在途计算需求；国家按优先级调度，粮源真实预留，道路共享装载容量，运输使用经费和不能同时生产/征募的民夫。行军军队在真实安全据点会合领取，不能远程取走未来粮仓。紧急征粮突破常规民食线有秩序代价；短期不足先伤士气，持续缺粮逐级减员，恢复粮食后重置连续缺粮日数。

低秩序和饥荒叠加中央危机/战争、主官与驻军态度时，地方可能提出归附。原属国有七日处置期，可赈济挽留；对方接受时支付保护预算，原子建立或复用战争、转移实际控制，保留法理，并记录盟约/停战责任。

## 表现、兼容与验证

共享地图画布的新图层显示原创步兵、骑兵、攻城器械、军旗与简化营地，依据统一的驻扎、训练、行军、战斗、围城、撤退状态表现。道路战斗优先于行程状态；远景降级为军旗，支持低画质和减少动态，模型失败保留原操作。

旧档保留资源、官职、军队与进行中战争，兼容单战争别名、旧统帅映射和军队围城镜像。旧档不补发预算、兵员或粮食；新增判定状态、真实转国与待决事项参与存档校验。数值声明清单已重建为 623 项，具体影响见数值审计。

141 项局部测试通过，生产构建通过，既有大分包提示保留。覆盖征募与军令回滚、私财边界、忠诚合分军、真实粮源/优先级/紧急征发、缺粮分级、阶段恢复、历史快照、双方及盟国议和、多战场独立清理、转国与归附幂等、保存失败回滚和恢复暂停。未运行长局或完整游戏回归，未做 UI 自动化验收。

## 军队遮挡与发黑修正 · 2026-09-30

- 庄园、城名、行旅人物、地理文字及事项徽记均在 DOM 层，单独提高 WebGL 模型层级无法避免遮挡。现在按可见标记的实际屏幕矩形避让；模型与点击区共用同一份位置，拥挤时回退军旗卡片，禁止拥挤卡片再次盖住模型。地图边缘限制在视口内，屏外军队不强行拉入；错位后保留细定位线。实际驻地、在途坐标、路线及军令目标仍来自世界状态。
- 原坐标变换使地图与模型的反射叠加，Three 的正背面判定与最终投影不一致，双面材质会翻转朝外法线。现将 Mercator 的 Y 轴转换统一放在场景边界，使模型与视图保持右手坐标系；分开真实视图和投影矩阵，恢复相机位置与光照计算，同时保持地图投影位置不变。
- 半球光按世界 Z 轴向上，补充反向柔光并调整铁、铜、皮革及织物底色。彩色图集仅作颜色贴图，不再冒充高度图；甲片、衣褶与器械结构的起伏由原网格保留。铁与铜按风化表面保留漫反射，处理无 HDR 环境的轻量地图通道；材质依据见 [Three.js MeshStandardMaterial 说明](https://threejs.org/docs/pages/MeshStandardMaterial.html)。模型比例按锚点投影导数计算，补偿透视和高程引起的尺寸变化。
- 几何检查发现旧点击区未涵盖俯视、转向时的马身及随军物件；预留范围扩大至 192×312 屏幕像素，人数牌仍在模型底部。所有新增矩形、偏移、比例与材质数值仅用于表现，不写入存档或参与玩法结算。
- 25 项局部测试通过：模型／卡片避让、同地及邻近军队、拥挤回退不盖住模型、边缘与屏外处理、行军坐标不变、三种倾角的相机投影一致性、右手坐标与正面法线约束、透视／高程比例、材质与双侧照明，以及真实步兵／骑兵／攻城网格在四种朝向、三种倾角、两种视口高度下的几何包络；另覆盖已有地图数据和样式约束。
- TypeScript 与生产构建通过，差异空白检查通过；保留既有大分包提示。游戏入口、军队图层／材质模块及图集 HTTP 均为 200。本次检查使用代码、网格及矩阵计算，未运行 GPU 画面验收、浏览器自动化、长局或完整游戏回归。
- 人工验收入口：[本地游戏](http://127.0.0.1:5173/)。重点查看庄园／事项附近的军队、甲片与衣物明暗、俯视及倾斜地图的转向、同地多军和 Shift 多选；实际外观、遮挡效果与帧率待用户确认。未推送或部署。

## 兵模定位与脸部修正 · 2026-09-30

- 上一版避让重新搜索屏幕空位、夹紧视口边缘，再把偏移反投影为另一处经纬度；缩放、平移或标注变化会使兵模跳动。现在 GPU 图层仅使用军队真实驻地／在途坐标及该坐标的地形高程，不读取标注偏移，不通过屏幕反投影重定位。模型边缘自然裁切，不拉进视口；庄园、城名、行旅人物与事项标注改为避让兵模，计算时扣除上次标注偏移以避免反馈漂移。
- 同地军队用稳定 ID 选择一组代表兵模，当前选中军队优先；密集地点减少重复模型，其余军队保留逐军旗牌和人数入口。实体、兵员、军权及军令不合并，选择切换不会把模型挪到别的地理位置。兵模定位要求已追加项目约定，避免后续再次以移动兵模解决标注遮挡。
- 头部改为连续网格，包含收窄的下颌／下巴、颧骨、凹入的眼窝和鼻梁／鼻尖；用嵌入眼窝的窄眼形、虹膜、上下眼睑、短眉和收敛的唇线替换球状五官及过宽黑嘴。头部封闭且无正面拼接缝，几何／材质仍共享缓存，每名士兵保留独立姿态；复用原甲胄、肤色及照明，不引入新的游戏人物数据。
- 近景人数牌原本位于模型中心，会在俯视时压住头部；现随地图倾角放到模型下沿，点击范围相应扩展至 192×348 像素。几何检查覆盖步兵、骑兵和攻城队在四种朝向、三种倾角、两种视口高度下的包络，确保人数牌不覆盖兵模。
- 局部验证共 37 项通过，覆盖锚点在平移／缩放／边缘的稳定性、同地换选与密度回退、标注避让、卡片选择与在途坐标，以及头部拓扑、法线、颌骨／眼窝、五官嵌入和共享缓存。图层 CPU 集成测试使用真实战役及征募入口创建的军队，经过四组相机／视口／高程参数，验证即使传入旧偏移仍投影在真实坐标，并禁止图层调用屏幕定位／反定位。
- TypeScript、生产构建和差异检查通过；保留既有大分包提示。本地游戏入口、图层、脸部模块和地图界面 HTTP 均为 200。测试隔离了 GPU 与 DOM 平台接口，验证代码、真实网格及矩阵调用链，不代表实际画面验收；未做浏览器自动化、长局或完整游戏回归。

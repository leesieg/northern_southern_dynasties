# 文档维护规范

本规范约定 `docs/` 的组织和维护方式。权限、工程、规则真实性及验收要求以 [项目约定](../AGENTS.md) 为准；文档总入口为 [文档索引](README.md)。

## 目录归属

| 目录 | 应存放 | 不应混入 |
| --- | --- | --- |
| `机制设计/` | 一个机制主题的规则说明、明确标注的建议及分期更正 | 全项目每日流水、原始对话 |
| `数值审计/` | 数值定义、影响关系、守恒与边界检查、生成字段清单 | 美术参数说明、未经追踪的结论 |
| `历史资料/` | 场景资料、史料依据、考据和模拟覆盖边界 | 将游戏平衡参数当作史实 |
| `art-direction/` | 美术方向、提示词、原始目标图、外观设计说明 | 未标明性质的实机截图 |
| `实施记录/` | 跨轮进度、实施事实、实际验证、未完成项 | 未获实施的提案写成成果 |
| `更新日志/` | 按轮次归档的玩家可见变化 | 只调研未落地的功能宣告 |
| `历史归档/` | 已退出主入口但需追溯的旧正文 | 当前规则的另一份平行副本 |
| `images/` | 已选入 README／文档的真实截图 | 临时截图、存档、构建与诊断日志 |

`docs/` 根目录仅保留总索引和本规范。源码与发布资源不迁入文档目录；外部设计输入留在 `chat/`，运行素材及署名留在 `public/`，模型源文件留在 `art/`。临时诊断、构建日志和验收过程截图放 `.cache/` 或 `.tmp/`，必要的正式文档插图才复制到 `images/`。

## 命名与导航

- 专题使用简短、稳定的中文名称；一个主题优先维护一份既有文档。已有的英文美术文件名与目录保留，避免无收益改名。
- 更新日志使用 `NNN-主题.md`，沿用当前轮次；编号空缺不补造，不把编号当版本号。仅路径迁移不新建游戏更新轮次。
- 只有需要并行保留的方案、素材或版本才在名称中加日期／版本，不为每次小改动新建文件。
- 新增、移动或归档后，同步更新总索引与相关日志索引。Markdown 链接相对当前文件写，代码、命令和资源路径按仓库根目录解释。
- 移动时保留正文与日期，修复仓库内链接、路径引用、生成脚本及项目规则。旧路径以 Git 历史追溯，不留重复正文或无用途跳转页。

## 内容与状态

新建专题或实质修订时，开篇简洁写清文档类型、适用范围、实际状态与核对依据。可用以下格式；只填写有证据的日期和版本：

```markdown
# 专题名称

类型：机制说明／设计提案／资料说明／美术目标／实施记录。
范围：本次覆盖的对象与机制。
状态：已实施部分、待实施部分、已被替换部分，以及待用户验收项。
核对依据：实际查看的代码位置、提交或史料来源；日期只记录真实核对时间。
```

- 既有文档可能跨多个迭代；保留原开篇与分期正文，通过明确日期的更正说明新行为。整理目录不刷新语义核对日期、不重写历史成果、不补认用户验收。
- 设计目标、已有实现、实际验证和人工验收分别说明。部分落地的文档应指出未完成范围；测试通过只覆盖实际执行的用例，不推定全局正确。
- 被替换的方案保留原记录，在相应段落或后续更正中指向新规则；不能靠文件名或目录暗示全部内容仍生效。
- 游戏参数与历史事实区分；资料列出来源与覆盖边界，缺失数据和推定结论明确标注。
- 实施记录写玩家可见变化、兼容与后果、验证边界、剩余事项；不复制长日志、完整聊天或密钥。

## 更新顺序

1. 规则变化先修改相应机制专题，按影响更新 [数值影响审计](数值审计/数值资源与机制影响审计.md)；仅字段声明变化时重建 [数值字段清单](数值审计/数值字段清单.md)。
2. 在已有 [实施记录](实施记录/迭代整合进度.md) 追加必要事实；需要独立一轮玩家更新时，再写日志并更新目录。避免同一内容在多处完整重复。
3. 新增专题或归档旧正文时更新 [总索引](README.md)；首页保留玩家阅读入口，不堆开发过程。
4. 检查本地链接、迁移路径、生成文件和 `git diff --check`。验证按实际改动范围执行，遵循项目约定，不借文档整理扩大游戏回归或 UI 验收范围。

字段清单由仓库根目录命令生成：

```bash
node scripts/audit-numeric-types.mjs
```

输出为 `docs/数值审计/数值字段清单.md`。不手工添加条目或改计数，不把生成清单当作机制正确性证明。

## 图片与归档

- `art-direction/` 的目标图注明“美术目标／参考”；`images/` 的截图注明功能、拍摄版本／日期（已知时）及本地与线上版本差异。
- 文档图片使用相对路径与有意义的替代文本；运行素材引用原位置，不为装饰复制一份发布资产。暂不用于文档的验收原图仍留在忽略目录。
- 归档前确定后续入口；保留必要来源、授权范围、兼容边界与验证事实。历史记录不作为新的授权来源，实际操作仍按当前用户指示和项目约定执行。
